# 《断弦之歌》Skill｜中文术语与通俗解释

> **中文阅读说明：** 这里就是给不熟悉英文生产术语时查阅的中文说明；实际执行以中文意思为准。

> **用途：** 看到英文标签时先查这里。英文主要用于文件ID、生产字段和模型Prompt兼容；实际理解以中文为准。

## 1｜六阶段相关

| 英文标签 | 中文 | 通俗理解 |
|---|---|---|
| Stage | 阶段 | 六步流水线里的某一步 |
| Scene | 场次 | 同一个时间/地点的一场戏 |
| Beat | 戏剧节拍 | 一场戏内部的一次明显变化/转折 |
| Shot | 镜头 | 摄像机不切开的连续一段 |
| Panel | 分镜格 | 宫格里的一个关键画面，不等于必须切镜 |
| Segment | 视频段落 | 一次丢给AI视频模型生成的完整小段 |
| Shot Purpose | 镜头目的 | 为什么要有这个镜头，它负责交代什么 |

## 2｜资产相关

| 英文标签 | 中文 | 通俗理解 |
|---|---|---|
| Master | 母图 / 主资产 | 下游反复调用的正式标准图 |
| Character Master | 人物母图 | 这个人是谁、现在穿什么 |
| Environment Master | 场景母图 | 这是哪里、空间结构怎么长 |
| Prop Master | 道具母图 | 这个东西到底长什么、比例多大、怎么用 |
| Base Master | 基础母图 | 没有特殊损坏/异常时的标准版本 |
| State Variant | 状态变体 | 还是同一个资产，但发生了长期剧情变化 |
| Master Set | 母图组 | 多张不同角度共同锁定一个复杂场景/资产 |
| Registry | 登记表 / 台账 | 现在有哪些正式资产、哪个版本可以用 |
| Human Scale | 人物比例参照 | 道具和手掌/人物身高到底是什么比例 |
| Render Style Anchor | 绘制画风锚点 | 只管“怎么画”，不管人物是谁 |
| Cinematic Shot Style Anchor | 镜头画风 / 摄影语法锚点 | 只管项目级镜头组织习惯，不覆盖具体Storyboard |
| Global Color DNA | 全局综合色DNA | 定义颜色如何组织、哪些职责由哪些色族承担；不是固定色卡、固定饱和度或固定天气滤镜 |
| Scene Color Extension | 场景综合色扩展 | 从Global Color DNA为新地点/气候/材质派生的综合色层 |
| Shot Lighting Variant | 镜头光色变体 | 当前Shot临时灯光/事件光色，不等于永久场景身份 |
| Reference | 参考图 | 给模型提供某一类明确职责的图片 |

## 3｜版本状态

| 标签 | 中文意思 | 能否正式下游使用 |
|---|---|---|
| WIP | 制作中 | 否 |
| CURRENT | 当前正在用的工作版本 | 视任务而定 |
| APPROVED | 已批准正式版本 | 是 |
| DEPRECATED | 已废弃 / 不再使用 | 否，禁止继续引用 |

## 4｜视频动作相关

| 英文标签 | 中文 | 通俗理解 |
|---|---|---|
| Entry | 起始状态 | 这段视频一开始人物/道具在哪里、什么姿势 |
| Trigger | 触发 | 哪个声音/动作/对白让变化开始 |
| Exit | 结束状态 | 这段最后停在哪里，下一段能直接接 |

| Continuity | 连续性 | 人物位置、方向、衣服、道具前后别跳 |

## 5｜表演相关

| 英文标签 | 中文 | 通俗理解 |
|---|---|---|
| Performance | 表演 | 人物如何用眼神、呼吸、身体表现情绪 |
| Listener Performance | 听者表演 | 没说话的人也要自然地听、反应，不要木头站着 |
| Reaction | 反应镜头 | 事件发生后拍人物怎么反应 |

| Establishing | 空间建立 | 先让观众明白人在哪里、空间关系是什么 |

## 6｜后期声音相关

| 英文标签 | 中文 | 通俗理解 |
|---|---|---|
| Ambience Bed | 环境底声 | 雨声、车声、房间底噪等持续背景声音 |
| Foley | 拟音 | 脚步、衣料、触碰等动作声音 |
| SFX | 音效 | 冲击、机械、异常声等效果音 |
| BGM Cue | 配乐节点 | BGM什么时候进、加强、停、退出 |

| L-cut | 声音延后切 | 画面先切走，上一场声音还留一下 |
| Picture Lock | 画面锁定 | 剪辑画面基本不再改时的正式状态 |

## 7｜QC

**QC = Quality Control = 质检。**

通俗说：这一阶段做完后检查“能不能放心交给下一阶段”。如果QC没过，就只回退修真正有问题的那一层，不要整条流程全部推倒重来。

## 8｜执行要求

- 面向用户输出默认使用中文。
- 英文标签第一次出现必须带中文解释。
- 不要求用户记英文缩写。
- 文件名、资产ID可保留在Workspace / Registry / Upload List等生产追踪层；Executable Generation Prompt默认不显示它们。
- 如果中文已经能准确表达，正文优先说中文。
- 不得因为用户不熟悉英文，就删除对生产有用的固定标签；正确做法是“保留标签 + 讲明中文”。

## 效率与复用术语

- **Batch Production（批量生产）**：把可以并行准备的资产、分镜一次处理，减少来回切换。
- **Candidate Triage / Best Take Selection（候选筛选）**：多张图片候选，或合法存在的多个Video Take，自动比较并推荐最佳候选；不代表全片默认要生成多个Take。
- **Scene Pack（场景生产包）**：同一场戏里反复复用的人物、环境、综合色和常用道具基础集合。
- **Reuse First（优先复用）**：已有APPROVED资产能满足当前剧情就不要重复生成。
- **Segment Delta（段落差量）**：当前Segment相对于Scene Pack新增、移除或改变了什么。
- **Continuity Snapshot（连续性快照）**：尾帧对应的简短文字状态，记录位置、动作、道具、摄影轴线等。
- **Ending Frame QC（尾帧质检）**：检查选作下一段起点的帧是否稳定清楚、可继续。
- **Retry / Escalation（返工/升级）**：先完整看结果并诊断；有明确问题就最小修Prompt，只有近似合格且疑似随机波动时才可选同Prompt再试1次，必要时再简化参考或拆Segment。
- **Prompt Compiler（提示词编译器）**：内部只修改错误模块，自动重新拼成完整Prompt。
- **Take（单次视频生成结果）**：一次视频生成得到的结果。正式流程默认从Take 01起步；后续Take只来自诊断后的重试/返工，或T3/T4已批准的受限候选预算。

## 归档与文件验证术语

| English Term | 中文解释 | 什么时候用 |
|---|---|---|
| Approved Asset Archiver | 已批准资产自动归档器 | QC通过且用户明确批准后，把真实文件自动保存到正式目录 |
| Archive Status | 归档状态 | ARCHIVED / ARCHIVE PENDING，用来区分“内容批准”和“文件是否真的保存” |
| Copy-first | 优先复制 | 自动归档默认复制正式副本，不随意移动/删除原候选 |
| Project Root | 项目根目录 | 实际生产资产、分镜、视频所在的顶层文件夹 |


| New Character Generation Recipe | 新人物统一抽卡配方 | 从已成功角色Prompt提炼出的通用生成结构，只继承画法和防写实策略，不复制现有角色长相 |
| Verified Prompt Strategy | 已验证提示词策略 | 已经通过实际生成结果证明有效的Prompt组织方式 |
| Style-only Reference | 只参考画法的参考图 | 可以看线稿、皮肤、头发和渲染，但禁止复制图中人物身份 |

| Physical Archive Commit | 真实文件归档提交 | 只有拿到真实源文件、复制成功、目标文件真实存在且源/目标SHA-256一致后，才把归档状态提交为ARCHIVED |
| Source Path | 真实源文件路径 | 文件系统里真正可读取的源文件位置；聊天预览、文件名或UI引用不算 |
| Filesystem Postcondition | 文件系统后置条件 | 复制后检查目标文件确实存在、是文件、大小>0且和源文件大小一致 |
| No File, No ARCHIVED | 没文件就不能标已归档 | 禁止只改Registry/Markdown却声称图片已经保存 |

- **WEB_MULTIMODAL_IMAGE_CAP（网页版多模态图片上限）**：由`adapters/web_qc/platform_profile.yaml`唯一配置；当前Profile为10张。超过当前上限必须进入下一Batch或Multi-Pass，不能硬塞。
- **WEB_QC_BATCH（网页版QC批次）**：B01 / B02等独立上传包；每批不超过当前Platform Profile图片上限，并重新从@图1编号。
- **WEB_QC_DEFAULT（网页版QC默认模式）**：视频生成后由网页版完整观看并验收，本地Skill只接收文字QC结果，避免重复消耗额度。
- **WEB_QC_UPLOAD_LIST（网页版QC上传清单）**：告诉你网页版这次必须上传哪个Video Take和哪些@参考图。
- **WEB_QC_COPY_PROMPT（网页版QC直复制提示词）**：本地Skill直接展示的一整段验证Prompt，已经包含本次@图职责、完整视频Prompt、检查方法和固定返回格式；整段复制到网页版即可。
- **Executor Input Map（执行器输入映射）**：内部记录“哪一个真实文件/平台输入槽位承担哪个Reference Role”的绑定表；包含Asset ID / Version / Input Mode，但默认不复制进生成Prompt。
- **Semantic Reference Role（参考图语义职责）**：内部Reference系统用于记录每张图究竟控制什么字段，例如环境、身份、构图、综合色或连续性。该Role用于Resolver / Binding / QC，不作为默认模型Prompt章节；交付生成模型前应消解成直接视觉执行语言。
- **WEB_QC_PACKET（网页版QC交接包）**：内部统称，实际由UPLOAD LIST + COPY PROMPT组成；不能只给Packet名字而不展示可复制Prompt。
- **External Video QC Report（外部视频QC报告）**：网页版看完视频后返回的结果。本地Skill导入后可直接决定PASS、修Prompt或可选重试。
- **LOCAL_SELF_CHECK（本地亲检）**：用户拿不准时主动要求Skill亲自读取视频复核；不是默认步骤，也不会自动触发。


## 战斗编排术语

| English Term | 中文解释 | 通俗理解 |
|---|---|---|
| Combat Choreography | 战斗编排 | 不只是“做动作”，而是安排谁为什么出手、怎么防、谁拿到下一步主动权 |
| Project Combat DNA | 项目战斗DNA | 《断弦之歌》长期稳定的战斗审美与判断方法，不绑定某一集 |
| Combat Design Brief | 战斗设计简报 | Stage 02先写清“为什么打、怎样算赢、主要难题是什么” |
| Victory Condition | 胜利条件 | 这场战斗怎样才算完成；不一定是把对方打倒 |
| Combat Archetype | 战斗原型 | 决斗、护卫、营救、破核心、追逐、多线协同等战斗类型 |
| Combat Profile | 战斗画像 | Skill根据当前人物武器、性格、音乐节奏、伤势等临时推导的打法 |
| Measure | 有效距离 | 现在这个位置，武器到底够不够得到 |
| Initiative | 主动权 / 节奏权 | 现在是谁逼着对方回应 |
| Combat Exchange | 攻防交换 | 一小段完整攻防：读招→出手→防守→接触/闪开→反击窗口→收招 |
| Commitment | 出招承诺度 | 这一招投入多深；越重的攻击通常越难临时收回 |
| Counter Window | 反击窗口 | 对方攻击落空、被偏转或收招时出现的短机会 |
| Near Miss | 险些命中 | 攻击擦身而过；常比连续真命中更有紧张感 |
| Impact Logic | 打击感逻辑 | 准备、加速、接触、压缩、传力、回弹、收招的完整重量链 |
| Tension Curve | 紧张感曲线 | 危险逐渐靠近→试探→真正接触→升级→失误/破防→兑现，而不是一直快 |
| Counterplay | 破解方式 | 一个技能除了“很强”之外，对手有什么办法读、躲、打断或反制 |
| Visible Cost Degradation | 可见式战斗衰减 | 不只说“累了”，而是让攻击距离、精度、步幅、恢复速度等真的变差 |
| Combat Conflict Audit | 战斗冲突审查 | 小说、设定、资产写法互相打架时，先分类和裁决，不偷偷拼在一起 |
| Synchronized Dissolution | 同步消散 | 战斗解除时，圣谱者武器、变身礼服和圣约指挥棒在同一解除阶段一起消失 |


## 表演、决策与世界状态术语

| English Term | 中文解释 | 通俗理解 |
|---|---|---|
| Actor Performance Engine | 演员表演引擎 | 先判断角色想要什么、用什么办法影响对方，再决定具体眼神和动作 |
| Given Circumstances | 规定情境 | 角色此刻已知的事实、关系、地点、时间和刚发生的事 |
| Objective | 当前目标 | 角色这一刻真正想从对方或场景得到什么 |
| Obstacle | 阻力 | 什么东西让角色没法轻易得到目标 |
| Tactic / Action | 行动策略 | 试探、安抚、隐瞒、逼迫、转移等角色正在采取的办法 |
| Active Listening | 主动倾听 | 不只是听到声音，而是接收信息并判断要不要改变自己的办法 |
| Adjustment | 策略调整 | 对方的新刺激让原办法失效后，角色换一种行动方式 |
| Beat Shift | 表演节拍变化 | 目标、策略、关系判断或场景事实真正变化时才进入新Beat，不等于句号 |
| Triggered Stillness | 有因静止 | 被某个刺激击中后短暂停住；这是表演，不是NPC冻结 |
| Ongoing Physical Task | 持续现实任务 | 整理纸张、修工具、开车等真实行为，用它承载心理变化 |
| Action Before Expression | 先行动后表情 | 不先堆皱眉/呼吸/握拳，再给这些动作找理由 |
| Performance Signal Preservation | 表演信号保留 | 有心理意义的眼神、呼吸、手部等不能因为模型难做就直接删 |
| Emotional Carrier | 情绪载体 | 这一刻观众主要从眼睛、呼吸、手、姿态等哪里看出情绪 |
| Visible Signal | 可见表演信号 | 把“害怕/关心”翻译成模型能看到的具体动作 |
| Psychological Counterforce | 心理对抗 | 害怕但强撑、想哭但忍住；两种力量同时存在反而更像真人 |
| Execution Conflict | 执行冲突 | 物理上不能同时发生的动作，需要改时序或动作设计 |
| Dialogue Performance Chain | 对白表演链 | 听见→理解→心里反应→压住/露出→说话→听者反应 |
| Natural Dialogue Performance Engine | 自然对白表演引擎 | 把多句对白当成持续思考和持续做事，而不是每说一句就停机重启 |
| Thought Intention | 思想意图 | 这一整小段话角色脑子里到底在完成什么 |
| Speech Phrase | 自然语流组 | 按语义、语速、情绪和真实换气需要组织的一段连续说话，不等于一个句号 |
| Body Continuity | 身体连续性 | 说话前正在做的事、姿态或注意力在多句台词中继续存在 |
| Continuity Bridge | 连续表演桥 | 两句话之间由视线、手部、姿态、表情状态或观察听者把表演接起来 |
| Breath Integration | 呼吸融入语流 | 普通呼吸是底层生理状态；只有有明确原因时才成为观众需要看到的表演信号 |
| Keyword Shift | 关键词转折 | 真正改变角色判断的词才推动眼神/动作/声音进入下一状态 |
| Listener Flow | 听者连续流 | 听者按意义变化改变状态，不按每句话逐句反应 |
| Subtext | 潜台词 | 嘴上说什么和心里真正想表达/隐藏什么之间的差别 |
| Speech-Body Coupling | 语言—身体耦合 | 台词的语速、停顿和身体动作一起表现真实状态 |
| Combat-Performance Coupling | 战斗—表演耦合 | 战斗动作和眼神、呼吸、情绪泄露由同一个攻防事件触发 |
| Execution Consequence | 执行后果 | 重攻击后的后摇、惯性、站位暴露等，可从动作物理推导 |
| Lore Cost | 设定代价 | 圣约反噬、寿命、精神损耗等长期机制，没有Canon不能乱编 |
| Decision Authority | 决策权 | 能由Skill自己判断的导演问题，不再反问用户 |
| OPEN_NONBLOCKING | 未定但不阻塞 | 长期设定还没拍板，但当前Scene可以不写死继续做 |
| ASK_REQUIRED | 必须询问 | 真正会改变Canon且现有Authority完全无法裁决时才问用户 |


### World State Continuity Engine｜世界状态连续性引擎
不是要求把所有过程拍出来，而是检查“上一状态怎样合理变成下一状态”。车还在开却下一镜已经站在剧院深处、道具无因消失、伤势只因换Scene自动恢复，都属于它要抓的问题；**完整变身完成触发的Transformation Recovery则属于有因世界机制，不算错误。**

### World State Ledger｜世界状态账本
记录当前地点/时间/移动状态、谁在场、关键道具在哪里、伤势/湿度、谁知道什么、环境破坏等。它回答“世界现在到底是什么状态”。

### Transformation Recovery｜变身修复
角色成功完成合法完整变身时，普通可恢复伤口可以在变身完成点真实恢复。恢复的是身体伤势World State，不等于把旧衣物血迹、环境破坏、永久疤痕、独立疲劳或圣约代价一起清零；解除变身后已恢复伤口也不会自动回来。

### State Diff｜状态差异检查
把上一段Exit和下一段Entry逐项比较，找出“移动→停止、车内→室外、道具手持→收入口袋”等变化，再决定哪些必须让观众看见。

### Minimum Necessary Bridge｜最小必要过渡
只拍足以让状态落地的最少连接，不拍生活流水账。例如“车从雨中驶近并减速 → CUT人物正在下车”，不需要逐步拍刹车、手刹、安全带。

### Residual Bridge｜余波式过渡
过程可不完整展示，但下一镜保留“刚发生”的痕迹。例如车已经停下，但车身刚稳、雨刷/灯仍工作、车门正在打开，让观众感觉它刚到。

### SCENE_OPENING ≠ World Reset
新Scene可以不用上一段Ending Frame，但人物的道具、伤势、湿度、Knowledge、关系和已发生的环境状态不能因此清零。若伤势已经在完整变身时被合法修复，新Scene继承恢复结果，也不能把旧伤重新刷回来。


## 音乐战斗、电影打击与VFX术语

| English Term | 中文解释 | 通俗理解 |
|---|---|---|
| Musical Combat Translation | 音乐战斗转译 | 不把音乐贴成音符，而是让它决定什么时候动、怎么加速、怎么停、怎么收招和怎么协同 |
| Musical Time Grammar | 音乐时间语法 | Rest、Sustain、切分、渐强、对位等如何改变一场战斗的时间结构 |
| Musical Motion Grammar | 音乐运动语法 | 把音乐时间继续变成步法、武器路径、Commitment、Recovery和主动权交接 |
| Contact Point Lock | 接触点锁 | 明确“哪一部分武器打到目标哪里、力量往哪走”，不让命中含糊带过 |
| Force Direction | 力量方向 | 这一击到底把力量往哪个方向送，决定目标身体和环境怎么响应 |
| Compression | 冲击压缩 | 重击碰上的瞬间先被“吃住”一下，再把力量释放出去 |

| Impact Space Reserve | 冲击空间预留 | 分镜提前给被击退/推动的方向留画面空间，让力量真的改变构图 |
| Post-Impact Vacuum | 冲击后真空 | 剧情级重击后短暂减少声音信息再恢复，只给真正重要节点 |
| New Combat State | 新战斗状态 | 一次攻防后距离、主动权、武器、破坏、持续场都更新，下一段从这里继续，不重新摆起手式 |
| VFX Identity ≠ Color Swap | 特效身份不等于换颜色 | 不同角色应该连节奏、几何、运动、接触和衰减都不同，不是同一个光炮换金/蓝/红 |


## 图片资产比例术语

### Asset Aspect Ratio Authority｜图片资产画布比例权威
通俗说：**先看这张图是干什么的，再决定横竖比例。** 不能因为最终视频是16:9，就把所有Stage 03资产都做成16:9。

### Character 9:16 Lock｜人物9:16锁
`DV-01 / DF-01 / DF-02 / EX-01 / HA-01 / TF-01 / TH-01 / TC-01`这类负责人物身份或完整造型的资产，默认9:16竖版。2×2只是排版方式，不代表整张图要横版。

### Ratio Authority Isolation｜比例职责隔离
Style Board / Color Card可以是4:3、16:9或竖版；它们的版式只服务信息组织。Storyboard的16:9只说明最终镜头，Video的16:9只说明成片；这些都不能决定人物母图比例。


## 个人创作者成本效率术语

- **Static-First Stop Gate（静态优先停机闸门）**：图片上已经能看见的硬错误先停在图片阶段修，不花视频额度验证。
- **Master Freeze + Local Patch（母图冻结+局部补丁）**：正式母图大部分正确时只修错的局部，不整张重抽。
- **Location Investment Tier（场景投资等级）**：L1单视图、L2走位关键、L3核心反复场景；按连续性需要决定做多少角度。
- **Shot Investment Tier（镜头投资等级）**：T1功能、T2普通叙事、T3复杂、T4英雄镜头；决定上游检查强度与Take预算。
- **Cinematography Grammar（摄影语言语法）**：按需说明机位高度/方向、Lens Family、Focus、Stabilization和相邻镜头关系；不是每镜头填摄影教材。
- **Camera Motion Contract（摄影机运动契约）**：把“推/摇/移”等写成摄影机真实怎么移动，避免模型把Dolly做成Zoom。
- **Failure-before-Compute（重生成前判断）**：每次额外花视频额度前先判断回上游修是不是更便宜、更稳。
- **Hero Shot Budget Concentration（英雄镜头预算集中）**：有限算力优先砸在观众会记住/截图/转发的关键镜头，而不是平均撒给全片。


## 日常服装与角色衣柜
- **Project Wardrobe Canon（项目服装总审美）**：全剧共享的是20世纪70—90年代欧洲现实服装世界与材质/综合色边界，不是同一穿搭模板。法式都市简约只是其中一种角色子语言。
- **Character Fashion DNA（角色服装DNA）**：这个人一贯“怎么穿”的规则，不是某一件固定衣服。
- **Character Closet（角色衣柜）**：这个角色实际拥有、以后还能继续穿的单品与Approved Look的文字登记表。不是要求给每件衣服都生成一张图。
- **Closet-First Outfit Assembly（衣柜优先搭配）**：换季/换场合先从已有衣柜重新搭；真的缺东西才新增。
- **No Lazy Styling（禁止懒惰式搭配）**：已有Look加大衣/围巾本身完全合法；真正禁止的是机械加功能件却没有重新处理比例、开合、层次、材质、综合色、Body Presentation与人物穿衣动机。
- **Wardrobe State Ledger（服装状态台账）**：记录当前穿哪套LOOK、脱了什么、拿着什么、衣服湿不湿/脏不脏/破没破。
- **Appeal Preservation Under Wardrobe（服装下魅力保留）**：天气/功能可以改变裸露方式，但成年角色既有身材线条与剪影魅力不能无理由被服装抹掉；冷天可改用肩腰比例、长腿线、手套/前臂、背部、衣摆等方式表现。


## 局部重绘 / Inpaint权限

| 术语 | 通俗解释 |
|---|---|
| EDIT_TARGET / REVISION_SOURCE_IMAGE | 真正要被修改的那张现有图片；可以是母图，也可以是QC失败候选。若说“修改候选A”，这里必须就是候选A |
| Task-Bound Reference Binding | 先判断当前在生成/修改什么，再只@当前任务最直接需要的参考图 |
| Negative Relevance Gate | 具体人物/地点/道具只有存在真实污染路径时才写进负面限制；当前输入里没有的实体不为了保险点名 |
| REFERENCE_RELEVANCE_FAIL | 当前图片输入没有直接职责、不是最直接Authority或与当前Shot/Task不匹配 |
| REVISION_TARGET_BINDING_FAIL | 说要修改某张候选，却没有把该候选绑定为真正的待修改输入 |
| NEGATIVE_RELEVANCE_FAIL | Prompt点名禁止当前输入里根本没有、也没有污染路径的具体实体 |
| PATCH_DESIGN_AUTHORITY | 重绘图案/正确局部结构参考；回答“这个局部要改成什么样” |
| MASK_REGION | 唯一允许重绘的区域 |
| FROZEN_REGION | Mask外不能借机改动的区域 |

## 系统完整性 / 复检 / 音乐同步术语
- **QC Scope Freeze（复检范围冻结）**：上一轮已经PASS且本轮没被修改触及的维度继续冻结，只复检真正开放的问题。
- **Revision Surface（修订影响面）**：本轮到底改了哪里、哪些规则可能被连带影响。
- **Dependent Integration Region（依赖整合边缘）**：Inpaint主Mask旁边只为阴影/反光/遮挡/接缝做最小物理适配的小区域。
- **Instance Map（重复实例映射）**：同一道具/结构在多视图重复出现时，列出所有必须同步修的实例。
- **Wardrobe Visibility Escalation（服装可见性升级）**：脱外套后露出此前未定义的大面积内搭时，回Stage 03补最小视觉Authority，而不是让分镜猜。
- **Visual Beat Map（视觉拍点图）**：记录Phrase Start / Hold / Major Contact / Cadence等画面时间结构；Approved Video后再记录真实时间戳交给Stage 06配乐。
- **Protected Sync Point（保护同步点）**：关键Hit/第四拍/断裂等不应为了现成BGM随便移动的视觉落点。
- **STALE_PROMPT（过时Prompt）**：上游Approved Authority已经变更，使尚未执行的旧Prompt不再可靠；只做最小重编，不全量推翻。


## 导演自主时长

- **Director Target Duration（导演目标时长）**：这段剧情真正需要多少秒，由导演根据Beat、对白、表演、动作和运镜判断；不是模型最大时长。
- **SKILL_DURATION_CEILING = NONE**：Skill不再设置单次AI视频生成的固定秒数上限；时长由导演自然目标与当前真实平台能力分开处理。
- **PLATFORM_DURATION_SPLIT_REQUIRED（平台时长约束拆分）**：只有当前平台明确Hard Max且无法容纳Director Target时，才在自然Beat/CUT/动作落点拆Segment。
- **No Duration Padding（禁止凑时长）**：内容自然完成后就结束，不为了平台更长Slot或默认时长增加无信息内容。
- **No Forced Time Compression（禁止硬压时长）**：不得为适配当前平台时长上限把对白/动作硬加速；必要时自然拆分或回Director Judge。
- **Platform Duration Profile（平台时长能力）**：当前平台真实支持的自定义时长、固定Slot或Hard Max；只有被用户/UI/任务可靠确认后才使用，Skill不硬编码。


## 参考图保真防火墙

- 高清人物/场景/道具母图 = 对象结构、材质、细节来源。
- 九宫格/4格/6格/故事版 = 镜头与动作视觉控制；平台支持Board可整板，支持多图可拆Panel，格数不固定。
- 尾帧 = 连续性控制。
- Render Style Anchor = 绘画语言控制。
- Cinematic Shot Style Anchor = 项目级摄影语法控制，不覆盖Storyboard。
- Global / Scene Color Reference = 对应层级综合色控制。
- Shot Lighting Variant = 当前镜头临时光色控制。
- 低清控制图不能因为放大就变成高清母图。

## 保留能力｜动作可行性与肢体-道具连续性

- **Action Feasibility（动作可行性）**：动作写进视频提示词前，先证明角色当前身体资源真的能完成它。
- **Limb Occupancy（肢体占用）**：某只手/脚现在是不是已经在拿东西、支撑身体、接触目标或受伤受限。
- **Support Graph（支撑图）**：记录“这个物体/身体重量现在靠谁支撑”。持伞手离开前必须先建立新的支撑，否则就是悬空。
- **Action Preconditions（动作前置条件）**：摸到、抓住、坐下、迈步、踢击之前必须先满足可达、空闲肢体、接触、握持或重心转移等条件。
- **Minimal Physical Resolution（最小物理解）**：不改变剧情意图的前提下，用最少动作解决冲突，例如优先用空闲手。
- **Micro Action Bridge（微动作桥）**：为了让动作成立而补的最短连接动作，如左手先接住伞柄、右手再释放。
- **ACTION_FEASIBILITY_FAIL**：动作在身体/道具层面尚未成立的硬失败状态；Stage 05不得继续输出FINAL VIDEO PROMPT。
- **Action Exit State（动作结束状态）**：动作完成后明确手、道具、支撑、接触与身体姿态在哪里，防止下一Beat随机重置。


## 自然动作与提示词语义去重

- **Natural Motion（自然动作）**：动作已经物理成立后，再判断真人怎样准备、启动、叠接、减速和落位。
- **Kinetic Chain（人体动力链）**：眼、头、肩胸、骨盆、脚等部位按动作幅度先后跟随，不像机械轴一起转。
- **Functional Preparation（功能性准备）**：真正完成动作必须先做的准备，例如站起前重心前移、拿杯前先建立握持。
- **Motion Corridor（运动走廊）**：Storyboard两个静态姿势之间的真实过渡过程，避免模型把Pose A直接插值到Pose B。
- **Action Overlap / Coarticulation（动作叠接）**：能同时自然发生的动作不要机械排队，例如步幅变短时手已经开始抬起。
- **Minimum Sufficient Motion（最小充分动作）**：只做足以表达当前意图的动作幅度，克制人物不因为情绪强就全身大动作。
- **Residual Motion（残余运动）**：主体停下后，衣摆、头发、伞或包等因惯性产生短暂、自然衰减的余韵。
- **NATURAL_MOTION_FAIL**：动作逻辑没错，但自然运动路径未解决时的硬失败。
- **Semantic Prompt Dedup（提示词语义去重）**：同一事实只保留一次最合适表达，不在多个区块复读。
- **Fact Owner（事实归属）**：决定某条信息应该唯一写在哪个Prompt区块。
- **Integrated Shot Timeline（整合镜头时间轴）**：视频Prompt里时间变化的唯一主执行区，把表演、动作、群体和环境反馈按真实时间点合并。
- **Negative Mirror（负面镜像重复）**：正向已经写清“右手持续撑伞”，又再写“不要让伞悬空”的重复。
- **PROMPT_REDUNDANCY_FAIL**：发现同义/跨模块/旧补丁叠加重复时，Prompt不得交付。

## 群体存在感与环境生命

- **Crowd Presence（群体存在感）**：背景多人在时间中持续存在，不因为前景对白突然变成静态截图。
- **Crowd Cluster（群体小簇）**：不逐人导演，而是按空间/活动把群众分成几组，例如靠窗聊天、柜台工作、入口进出。
- **Crowd Motion Field（群体运动场）**：记录不同区域的人流方向、速度、密度和停留活动。
- **Ambient Motion Contract（环境生命运动契约）**：一个Segment里背景必须持续的少量低强度活动，保证世界没有Pause。
- **Crowd Attention Map（群体注意力图）**：群众主要关注自己、同行者、任务、环境还是前景；主角重要不等于群众都看主角。
- **Reaction Propagation（反应传播）**：巨响/危险等刺激由近到远、分批、不均匀传播，禁止全体同步转头。
- **CROWD_PRESENCE_FAIL**：群体生命逻辑未解决时阻止Stage 05继续编译的硬失败。

## 主资产优先与镜头覆盖

- **Canon Master（正式主资产）**：先用一张高质量图定义“这个道具/场景到底长什么样”。
- **Shot Coverage Matrix（镜头覆盖矩阵）**：Stage 02按实际镜头检查会拍到道具哪一面、场景哪个方向。
- **Derived Coverage View（衍生覆盖视图）**：只有主图不够覆盖真实镜头时，才从主图倒推补出的高清角度/状态图。
- **Parent Master（父母图）**：所有衍生视图必须继承的正式主图，衍生图不能重新设计。
- **ASSET_COVERAGE_GAP（资产覆盖缺口）**：Stage 04发现某个镜头确实需要一个此前没准备的正式道具结构面/场景方向；只回Stage 03补这一张，不重做整个资产。
- **Video Risk-Driven Static Reference Matrix（视频风险驱动静态参考矩阵）**：导演锁镜头后检查“还有哪些关键静态事实不该留给昂贵Video自行猜”，并决定由Coverage、Persistent State、Stage 03 Production Support、Stage 03 Shot Assembly或Stage 04 Video Conditioning解决。
- **Production Support Reference（生产辅助参考图）**：不改Canon、只为当前高风险生产任务提供高清Interaction / Contact / Transient State / Entity Action / Scoped Minor Prop / Shot Detail证据的Stage 03图片；批准状态是`APPROVED SUPPORT`。
- **Shot Assembly Asset（镜头组装资产图）**：当人物、场景、道具、当前状态大体已定义，但Video仍可能对“这一镜怎么把它们放在一起”进行大量猜测时，Stage 03先生成一张高清静态镜头组装图；它是`APPROVED ASSEMBLY`，不是Storyboard。反复/命名人物继承正式Character Authority；一次性`SCOPED_CAST / NON_RECURRING`也必须先继承Approved FMH/Minor Human Master，Assembly只锁当前同框关系，不建立人物基础外观。
- **Lightweight Interaction Prop Reference（轻量交互道具参考）**：低复用、不值得建项目级Prop Master，但当前镜头会清楚拿/递/操作的小物件高清参考；若后续重复使用或成为关键线索则升级正式Prop Authority。
- **Shot Detail Reference（镜头局部参考）**：一次性Insert/Close-up必须看清、但不值得建立长期Detail Master的局部高清证据；不得用来发明长期Canon结构。
- **Video Conditioning Frame（视频执行帧）**：Approved Clean Storyboard之后，把已锁Camera/Blocking + SPATIAL_CANON + Approved对象Authority + 当前State落实成当前Video Unit的First/Target/Last/Key/Contact/Exit/Entry静态视觉输入；至少一个Primary Frame为必需，高风险才增加额外帧。
- **HD_PRODUCTION_SUPPORT_IMAGE（高清生产辅助输入）**：Production Support的辅助输入模式，只在授权字段中生效；不能无因覆盖人物身份、对象Canon或场景Geography。
- **VIDEO_RISK_REFERENCE_GAP（视频风险参考缺口）**：本来能在昂贵Video前用静态高清图解决的关键歧义仍未解决时触发的硬阻塞。
- **SUPPORT_REFERENCE_AUTHORITY_FAIL（生产辅助参考越权）**：Support重设计Canon、改Storyboard、长期冒充Persistent State或与Coverage/State重复抢同一字段时触发。
- **本规则不改Character资产体系。**

## Current Reference Completeness补充术语
- **Key Visible Asset（关键可见资产）**：当前Storyboard/Video里会被清楚看见、操作、特写或承担因果的主要人物、场景方向、道具/武器/载具/实体/状态。
- **SCOPED_CAST / NON_RECURRING（限定范围一次性人物）**：只服务当前Scene/Shot Group、后续不需要身份连续的一次性人物。Stage 02必须先建`SCOPED_CAST_BRIEF`；只要清楚可见就建立一张FMH/Minor Human Master作为独立Appearance Authority，Shot Assembly/Previs只补关系和动作；真正深背景才TEXT_ONLY。若后来重复出现、需要反打/背面或跨Scene识别，则升级Minor Human View Set或正式Character Canon。
- **FMH / Functional Minor Human Asset（功能性小人物资产）**：一次性匿名人物的最小视觉Appearance Authority，状态`APPROVED SCOPED FIGURE`；不等于完整Character Master，也不负责最终场景站位。
- **Reference Field Coverage Map（关键可见资产参考覆盖表）**：先列出当前镜头必须视觉锁定的字段，再确认每个字段由哪张Approved图承担；目标不是图片越少越好，而是关键资产全覆盖、冗余图不占位。生成Prompt只写职责，不写内部Asset ID。
- **Minimum Sufficient Reference Set（最小充分参考集）**：所有Critical字段都被覆盖后的最紧凑集合；如果关键资产多，可以自然包含多张图。
- **REFERENCE_COVERAGE_GAP（参考覆盖缺口）**：关键可见资产没有视觉Authority，禁止继续Storyboard/Video。
- **REFERENCE_SLOT_OVERFLOW（参考槽位溢出）**：关键资产都需要，但平台槽位不够；不能静默删关键图，必须重组Assembly/Anchor/TEXT_CONTROL或调整Segment。


- **Face Identity Matrix（面部个体识别矩阵）**：把脸型、面中、下颌、鼻唇、眉眼关系等锁成角色专属结构，避免全员同脸。
- **Hair Identity Architecture（发型身份架构）**：从远景剪影、中景结构、近景发束三层锁住每个人不同的发型。
- **Wardrobe Diversity Matrix（服装多样性矩阵）**：同一时代/世界下，通过廓形、比例、领口、层次、材质、鞋靴和穿衣习惯建立不同衣柜。
- **Character Template Collision（角色模板碰撞）**：两个角色主要只靠颜色、发色或衣服区分，Face/Hair/Eye/Wardrobe/Adornment结构高度相同。


## Personal Adornment / Character Requirement术语
- `Adornment ID`：人物个人装饰识别层；不是随机首饰，而是稳定佩戴习惯/形状/位置/材质。
- `Character Asset Requirement Set`：主要/反复/可变身人物在本集真正必须完成的身份资产集合；默认DV-01 + DF-02 + HA-01，DF-01 / AD-01 / PR-01按实际镜头需要。
- `AD-01`：Signature Adornment Detail；只有近景需要且Current Look不足以锁定时才生成。
- `ADORNMENT_ASSET_GAP`：装饰已成为关键可读字段，但缺直接Approved Authority。
- `ROTATING`：从已批准Rotation Pool按LOOK/场合轮换，不是随机换首饰。


### Body Identity / Body Presentation
- `Body Identity`：人物本身稳定的身高、肩胸腰胯腿等身体身份，不随衣服改变。
- `Body Presentation Mode`：当前这套LOOK用什么方式让身材美被感知；可DIRECT、FRAMED、PROPORTIONAL、IMPLIED、CONTRAST或MIXED。
- `Transformation Body Presentation Mode`：变身礼服专属的身体呈现方式；继承同一Body Identity/Appeal，但不要求照搬Daily LOOK的模式，礼服可以通过负空间、框景、比例、材质和动态同步强化人物身材美。
- `Source Wardrobe Adaptation`：小说只锁真正影响剧情的服装事实；普通服装描写只是参考，最终美术由Skill决定。
