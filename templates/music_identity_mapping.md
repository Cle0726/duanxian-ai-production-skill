# Music Identity Mapping（人物性格 → 音乐风格 → 视觉设计映射）

> **用途：** 把《断弦之歌》人物的性格、情绪命题与人物弧光，转译成可执行的音乐身份，再由音乐身份推出变身美术五核心、动作节奏与FX。它是“人物为什么会长成这种圣谱者”的中间桥梁。

## 1｜核心链路

**Personality / Emotion（人格 / 情绪）**
→ **Music Identity（音乐身份）**
→ **Rhythm Profile（节奏画像）**
→ **Visual Grammar（视觉语法）**
→ **Transformation Beauty Core Five（礼服 / 眼影 / 头发 / 瞳孔 / 音乐武器）**
→ **Motion / FX（动作 / 共鸣演出）**
→ **Musical Combat Translation（战斗时：音乐时间语法 → 战术/武器运动 → Impact/VFX）**

禁止直接从“角色颜色”开始设计。

**持久化与场景叠加必须读取 `music_identity_registry.md`。** 稳定的Character Leitmotif不能因为单场悲伤/回忆/愤怒被直接改写；Scene Emotion与Action Intensity只能作为临时Overlay。

## 2｜信息来源等级

### A. Canonical Music Identity（剧情正式音乐身份）
剧情、角色总表、世界观或用户已批准资料明确写出的：
- 乐器 / 声部；
- 曲式 / 音乐类型；
- 明确的角色音乐主题；
- 已确认的曲名、调式、作曲家等。

这些属于正式设定，下游必须继承。

### B. Derived Music Direction（推导音乐方向）
如果剧情只提供“悲伤、回忆、狂热、保护、危险”等人格/情绪，而没有具体音乐术语，Skill可以为了美术生产推导：
- broad music family（宽泛音乐家族）；
- tempo feel（速度感）；
- rhythm character（节奏性格）；
- dynamics（力度变化）；
- timbre metaphor（音色隐喻）。

但必须标记为 `DERIVED / 待批准推导`，不能冒充世界观已写死的Canon。

### C. Technical Music Facts（专业音乐事实）
具体大调/小调、调号、和声功能、具体古典作品、作曲家或专业演奏术语：
- 来源未明确时不得为了“显得专业”自行硬编；
- 用户未批准前不得写回角色Canonical设定；
- 如后续需要正式音乐学准确性，应单独核验。

## 3｜Music Identity Card（音乐身份卡）

每个正式圣谱者最少建立：

- `Emotion Core`｜情绪核心：悲伤 / 狂热 / 怀旧 / 冷静 / 自由 / 压抑 / 危险等；
- `Personality Core`｜人格核心：保护、控制、反抗、修复、独奏、秩序、逃离等；
- `Dramatic Wound / Desire`｜创伤 / 欲望；
- `Music Family / Style`｜音乐家族 / 风格；
- `Instrument / Voice`｜乐器 / 声部（剧情支持时）；
- `Tempo Feel`｜速度感：slow / moderate / driving / unstable；
- `Rhythm Profile`｜节奏画像：强拍、切分、摆动、重复、断拍、长延音、回环等；
- `Dynamics Profile`｜力度画像：持续压低、骤强、渐强、爆发后收束等；
- `Timbre Metaphor`｜音色隐喻：木质低音、金属锐响、雾化人声、旧唱片颗粒等；
- `Phrase Shape`｜乐句形状：上扬、下沉、弧形、破碎、重复、追逐；
- `Visual Grammar`｜对应的线条、轮廓、材质、对称、综合色；
- `Large-form Translation`｜音乐怎样改变体量、比例、轮廓或Weapon-Body关系；
- `Negative-Space / Graphic Translation`｜音乐怎样改变开口、空洞、色块、重复/断裂；
- `Material Contrast Potential`｜音色怎样转译为硬软、透不透、哑亮、新旧等反差；
- `Beauty Core Five Translation`｜五核心如何分别承接音乐身份；
- `Motion Grammar`｜战斗 / 变身动作节奏；
- `Forbidden Mismatch`｜最不应该出现的音乐/视觉错配。

## 3.1｜Bold Structural Translation（音乐身份的大尺度转译权限）

Music Identity不是“主色+音符纹样”生成器。对核心圣谱者，允许音乐身份直接改变**大轮廓、身体负空间、裁片比例、材质对撞、发型体量与武器-身体关系**。

优先问：
- 节奏能否变成服装重复 / 断裂 / 切分 / 非对称？
- 长音 / 延音能否变成长拖尾、连续大曲线或悬浮体量？
- Staccato / Break能否变成分离裁片、孔洞或跳跃式色块？
- Counterpoint能否变成两个层级明确、互相穿插的结构？
- Timbre能否变成材质的硬/软、透/不透、哑/亮反差？
- Resonance能否改变虹膜、环形轮廓或Weapon-Body Silhouette？

允许“奇怪但漂亮”的非现实转译；不要在概念阶段因为“太夸张”就先修回普通礼服。功能性检查应在强概念成立之后解决可执行方式。

标准Notation可以使用，但不是必需终点；`DERIVED_MUSICAL_GLYPH / MUSICAL_GEOMETRY`同样是正式音乐视觉语言。

## 4｜不是“一种性格 = 一种音乐”

禁止机械字典式映射。

例如“悲伤”可以是：
- 安静下沉的长音；
- 压抑后突然爆裂的摇滚；
- 带回忆重复动机的旧式舞曲；
- 冷静、近乎无情绪的室内乐。

因此必须同时读取：
**稳定Character Leitmotif + 当前人物弧 + 创伤/欲望 + Scene Emotion Layer + Action Intensity Layer + 已有音乐设定。**

例如：Rock角色进入悲伤回忆Scene时，仍保留Rock的核心节奏/音色身份，只把速度、力度、停顿与动作能量压低；不能因为“悲伤”就换成另一套角色音乐人格。

## 5｜常见音乐方向的视觉转译示例

这些是**设计词库，不是角色硬锁**。

### Rock / 摇滚型
音乐感：强拍、切分、冲撞、爆发、失真边缘。
- 礼服：锐利切角、不对称、短长对冲、强负形；
- 眼影：锋利外扩、刮擦/裂音感；
- 头发：更强发束张力与受冲击运动；
- 瞳孔：断裂、尖锐、强拍式几何；
- 武器：可借鉴拨弦/击弦/扩音结构与强击动作，不直接“吉他加刀”；
- Motion：启动快、停顿狠、爆发后快速收束。

### Sorrow / 悲伤型
音乐感：长延音、下沉、留白、回响。
- 礼服：垂坠长线、下沉重心、克制层次；
- 眼影：柔长、低位、像残留谱墨/泪痕但必须角色唯一；
- 头发：更慢、更重、更有余韵；
- 瞳孔：回声环、残音结构、向内收束；
- 武器：细长、距离感、延迟感或“蓄积后释放”；
- Motion：慢启动、延迟、余韵长。

### Memory / 回忆型
音乐感：重复动机、旧质感、回环、模糊边界。
- 礼服：层叠、半透明旧影、重复纹样但不做旧纸插画；
- 眼影：轻雾、残影、断续重复；
- 头发：边缘柔化、局部重复饰件/发束节奏；
- 瞳孔：回环、同心、残缺重复符号；
- 武器：像“承载过去的器物”但必须仍可战斗；
- Motion：回头、停顿、动作重复后发生微小差异。

### Waltz / 圆舞曲型
音乐感：三拍流动、旋转、优雅但可隐藏危险。
- 礼服：旋转时读形的弧线与裙片；
- 眼影：弧形/偏心回旋；
- 头发：旋转惯性与连续曲线；
- 瞳孔：三分结构、回旋环；
- 武器：适合旋转、牵引、圆周轨迹；
- Motion：连续转体、三段重心转移。

### March / 进行曲型
音乐感：规则、推进、强拍、秩序。
- 礼服：纵向、重复节拍、明确肩线；
- 眼影：几何、短促、规则；
- 头发：结构稳定、变化范围受控；
- 瞳孔：刻度、重复节拍单元；
- 武器：直线推进、守阵、压迫空间；
- Motion：明确起拍、推进、止步。

### Aria / 咏叹调型
音乐感：人物中心、情感展开、呼吸与长句。
- 礼服：强调人物中心与歌剧性轮廓；
- 眼影：精致、沿眼神方向延伸；
- 头发：有呼吸感和长线条；
- 瞳孔：主题性强、精细、近景识别度高；
- 武器：与“独唱/表达/穿透”相关，不必巨大；
- Motion：呼吸 → 延展 → 高潮 → 收束。

## 6｜Beauty Core Five Translation（五核心映射）

从Music Identity Card到美术必须逐项写：

### Costume
音乐的节奏与乐句怎样变成：轮廓、裁片、开口、层次、重量？

### Eye Makeup
音乐的重音、残响、裂音、回环怎样变成：眼影轮廓、眼线、眼下纹样？

### Hair
音乐的速度、重量、流动怎样变成：发束、渐变边界、发饰、运动？

### Pupil / Iris
音乐的核心身份怎样变成：唯一Core Pupil Symbol + Iris Topology？

### Music Weapon
乐器/声部/演奏动作/节奏功能怎样变成：可握持、可攻击、可防御或可控制的武器结构？

## 7｜Motion Grammar（动作节奏映射）

角色的Music Identity不仅控制静态设定，也必须通过 `music_identity_registry.md` 跨Stage保存，并向Stage 04/05传递“Character Leitmotif + Scene Emotion + Action Intensity”合成后的动作语言：
- `Tempo Feel`｜整体速度感；
- `Attack Cadence`｜攻击节拍；
- `Acceleration / Deceleration`｜加减速方式；
- `Rest / Hold`｜主动空白/停顿；
- `Repetition / Variation`｜重复与变化；
- `Sustain`｜动作/控制的持续性；
- `Syncopation / Off-beat`｜在预期空档进入；
- `Counterpoint`｜独立动作同时成立并形成关系；
- `Crescendo / Diminuendo`｜逐步增加/降低动作与压力；
- `Recovery / Closure`｜动作回收与终止感；
- `Finisher Rhythm`｜终结技节奏；
- `Breath Pattern`｜乐句式蓄放、发力组织与动作“呼吸感”；**默认不是字面胸腔呼吸动画**。

### 7.1｜战斗转译

进入战斗时继续读取 `cinematic_combat_vfx_engine.md`：

**Music Identity → Musical Time Grammar → Footwork / Commitment / Weapon Kinetics / Tactical Timing → Cinematic Impact / VFX**

音乐术语不能只作为标签。Skill必须把它翻译为观众即使不懂乐理也能看懂的动作结果。可见音乐符号默认克制，只有Canon/Approved Asset已经确认且承担机制时使用。

注意：这是动作设计节奏，不要求视频模型自动生成真实乐理或具体BGM。只有Actor / Performance系统已经判定`Breath = VISIBLE_WITH_CAUSE`时，Music Motion Grammar才可与真实可见换气发生联系；否则只转译为Pause / Acceleration / Hold / Release等动作节奏。

## 8｜Post-production Handoff（后期音乐交接）

Music Identity Card可向Stage 06提供 `Music Cue Direction（配乐方向）`：
- 角色进入时需要什么速度感、音色、节奏重心；
- 战斗高潮何时增强或留白；
- 角色主题是否应该重复某个节奏/音色动机。

它只提供配乐方向，不自动指定版权音乐或未经确认的具体作品。

## 9｜QC

判定失败：
- 只写“悲伤=蓝色”“摇滚=黑红”而没有节奏/结构转译；
- 战斗中Music Identity只变成音符/五线谱/Glow，没有改变Timing / Footwork / Weapon Kinetics / Recovery；
- 只靠换颜色制造不同音乐风格；
- 五核心和Music Identity彼此解释不通；
- 武器与音乐身份无关；
- 所有角色虽然音乐标签不同，实际礼服/眼影/头发/瞳孔仍是同一模板；
- 剧情没有支持却擅自写死具体调式、作品或作曲家；
- Personality和Music Style明显冲突却没有剧情理由。

通过标准：
- 不看名字也能从五核心和动作语言感受到角色“听起来像什么”；
- 同一角色的音乐、视觉、动作形成同一人格；
- 不同角色即使综合色接近，也能依靠节奏、结构和武器逻辑区分。
