# Transformation Asset Standard（圣谱者变身资产标准）

> **用途：** 本模板用于《断弦之歌》所有剧情明确可变身的圣谱者 / Virtuoso。它规范“变身设计如何成立、需要哪些正式资产、变身过程怎样遵守世界观机制、下游如何引用”，但不重新定义已批准角色身份，也不替代 `project_style_dna.md`。
>
> **核心原则：Transformation is identity revelation, not costume replacement（变身不是换装，是身份显影）。**

## 1｜适用条件与防污染

只有当前Canon / `EPISODE SCREENPLAY LOCK`已明确角色具有圣谱者变身身份时，才进入本标准。

- 变身身份未确认：不得擅自生成音符瞳、变身礼服、圣谱者武器或变身序列。
- 新圣谱者必须先建立独立设计槽，不得通过“给现有圣谱者换颜色”快速制造。
- 已批准的 T01–T08 角色设计继续有效；本标准不重新设计其瞳孔、头发、礼服或武器。对既有APPROVED圣谱者先做Retroactive Musical Eye Registry Audit；若现有眼部缺少清楚的Primary Eye Signature / Musical Origin Trace，标记`LEGACY MUSICAL EYE GAP`并等待用户批准是否重设计，Skill不得静默改眼妆。
- 新角色若尚未有正式编号，先在项目角色数据中登记，再建立资产。

## 2｜变身设计的五个前置问题

在写任何 TF / TE / TH / TC / WP / TS Prompt 前，先回答：

1. **Origin / Transformation Type（来源 / 转化类型）**：角色如何成为圣谱者？自然诞生、强制转化、实验、培育、自愿登记、原谱共鸣或其他已被剧情确认的类型？
2. **Personhood State（人格状态）**：人格完整、受损、恢复中、被控制、重建、过载，还是其他剧情状态？
3. **Accord Mode（圣约模式）**：自愿、强制、失去、重建、培育；当前是否已有链接乐监？
4. **Character Theme（人格主题）**：角色当下最核心的选择、创伤、恢复、秩序、独奏、保护等主题是什么？
5. **Music Identity（音乐身份）**：读取 `music_identity_mapping.md`。从剧情明确的人格、情绪命题、人物弧与已有音乐设定建立Music Identity Card；剧情未明确的风格只能作为 `DERIVED / 待批准推导`。**不得为了显得专业而擅自编造具体大调/小调、调号、曲名、作曲家或专业术语。**

### 2.1 Design Translation（设计转译）

前置问题确定后，先执行：

**Personality / Emotion → Music Identity → Rhythm Profile → Visual Grammar**

再把这套视觉语法分配给 `Transformation Beauty Core Five（变身美术五核心）`：

**Costume（礼服） + Eye Makeup（眼影/眼周） + Hair（头发） + Pupil/Iris（瞳孔/虹膜） + Music Weapon（音乐武器）**

最后才生成Transformation / FX、谱线、饰件、圣约指挥棒等Supporting Layer。

同时读取`transformation_splendor_architecture.md`建立`Transformation Splendor Profile`：Costume Thesis / Style Family / Boldness Dial / Primary + Secondary Costume Signature / Graphic Block / Negative Space / Large-Medium-Small / Material Contrast / Hair Splendor / Weapon-Body Silhouette / Focal Chroma-Light。**华丽度与大胆设计是正向要求，不是“避免俗气”后的剩余结果。**

五核心必须共享同一套 `Visual Grammar（视觉语法）`：符号形态、线条节奏、材质、金属类型、色彩强调、对称/不对称关系、运动节奏之间能互相解释。详细规则读取 `transformation_beauty_core_five.md`。


### 2.2A Musical Eye Motif Gate（音乐图形化眼部签名闸门）

**任何圣谱者变身眼部都必须读取`musical_eye_motif_system.md`。** 先锁少数强Graphic Decisions：
1. `Primary Eye Signature`｜唯一主记忆点；
2. `Secondary Graphic Signature`｜MAIN/CORE必须；
3. `Periocular Emblem`｜0–1；
4. `Musical Origin Source / Translation Level / Origin Trace`；
5. Supporting Eyeshadow / Eyeliner / Iris / Side-view字段。

P0要求：
- `Eye Makeup Presence = MINIMAL / STANDARD / EXPRESSIVE`，不得NONE / ABSENT；
- Music Identity必须真正进入眼部Graphic，不只存在于颜色或外部饰品；
- 允许`LITERAL_NOTATION / DERIVED_MUSICAL_GLYPH / MUSICAL_GEOMETRY`；**不要求每个角色保留标准Notation图标**；
- 新设计必须读取`musical_eye_motif_registry.md`做全项目Graphic Signature Collision；
- 禁止“普通眼妆 + 眼尾贴音符”；
- 禁止为了证明独特而让5–8个眼部字段都成为同等级焦点。

P0失败：`MUSICAL EYE SOURCE LOST / MUSICAL EYE REGISTRY COLLISION / MUSICAL EYE READABILITY FAIL / MUSICAL EYE STICKER FAIL / EYE_SIGNATURE_OVERDESIGN_FAIL / MUSICAL EYE ABSENCE FAIL`。

### 2.2 Eye Signature Uniqueness Gate（眼部唯一签名闸门）

**任何 TF-01 / TE-03 Prompt 在正式生成前，必须先从Normal Character Master锁定`Base Eye Identity`，再建立`Transformation Eye Signature Spec`并与项目现有角色/圣谱者做跨角色撞型检查。**

Base Eye Identity至少记录：
1. `Base Eye Aperture`｜眼裂长宽与圆/窄结构；
2. `Outer-corner Trend`｜平 / 上挑 / 下垂；
3. `Upper / Lower Lid Geometry`；
4. `Brow-Eye Relationship`；
5. `Lash Organization`；
6. `Iris Scale / Default Gaze`。

Transformation Eye Signature至少记录：
1. `Core Pupil Symbol / Iris Architecture`；
2. `Eye Makeup Presence`（MINIMAL / STANDARD / EXPRESSIVE，禁止NONE）；
3. `Primary Eye Signature + Primary Channel`；
4. `Secondary Graphic Signature`（MAIN/CORE REQUIRED）；
5. `Periocular Emblem`（0–1）；
6. `Musical Origin Source / Translation Level / Origin Trace`；
7. `Graphic Eyeliner / Eyeshadow Silhouette`；
8. `Symmetry / Side-View Read`；
9. `Material Metaphor / Color Family`；
10. `Formation Sequence`；
11. `Cross-Core Echo`。

#### P0 Collision Rules（零容忍撞型）
- Core Pupil / Iris Architecture不能与现有角色高度重复且只换色；
- Primary Eye Signature不能只靠镜像、旋转、缩放或小位置变化伪装成新设计；
- MAIN/CORE的Secondary Graphic也不能与另一角色形成同套组合；
- 外部发饰、胸针、服装音符不能代替真正Eye Graphic；
- 男性MINIMAL眼妆仍需Primary Graphic，但不强迫贴标准Notation；
- Periocular Emblem只是Accent，不能成为“主设计其实一样”的遮羞布；
- 细节很多但一句话说不出Primary时，判`EYE_SIGNATURE_OVERDESIGN_FAIL`。

#### Structural Distinction（结构差异最低要求）
Base Eye与现有主要角色至少形成3项非颜色差异；Transformation重点比较：
`Primary Signature / Primary Channel / Secondary Graphic / Iris Architecture / Graphic Eyeliner-Shadow Silhouette / Symmetry / Side-View / Formation`。

若跨角色比较后仍可描述为“某角色眼睛换颜色”，判`EYE SIGNATURE COLLISION`，不得进入正式TF-01生成。

### 2.3 Eye Signature Ledger（眼部签名台账）

Skill不凭记忆假设项目已有圣谱者设计。生成新角色或重写现有角色TF/TE Prompt前，应优先读取：
- 项目角色总表 / 已有Transformation设定；
- 已批准TF-01 / TE-03；
- Asset Registry中已有眼部签名记录。

将当前已确认角色的Eye Signature Spec形成临时或持久 `Eye Signature Ledger（眼部签名台账）`，用于本次Collision Check。台账字段与撞型矩阵统一读取 `eye_signature_ledger.md`。

若项目资料不足以确认其他角色的眼部签名，不得自行补造；应标记 `UNIQUENESS REVIEW PENDING`，而不是虚构“已无撞型”。

## 2.4 Splendor & Presentation Gate（华丽度 / 图标化 / 导演展示闸门）

首次/核心变身正式TF / TH / TC / TE / WP生成前：
1. 读取Stage 02的`Transformation Presentation Requirement Draft`或已有Presentation Contract；
2. 先写`Costume Thesis`，确定开放的`Style Family`与`Boldness Dial`；
3. 锁2–3个Hero Costume Decisions，不先堆Small Detail；
4. 建立Graphic Block + Negative Space；
5. 再建立Large / Medium / Small Splendor、Material Contrast与Weapon-Body Silhouette；
6. 成人角色的性感权限、身体线条、暴露几何、极端比例可主动成为Hero Decision；不因“高级/成熟/克制”自动收回；
7. 读取`body_identity_presentation_authority.md`：继承Normal Body Identity与Appeal Hook，并为当前礼服建立`Transformation Body Presentation Mode + Body-Costume Interaction`；Daily Presentation Mode不要求原样复制；
8. Dark Gothic只是一种可选Style Family，不能成为默认圣谱者模板；
9. 资产Approved后把Actual Splendor Profile回交`director_spatial_reconciliation_gate.md`，完成`TRANSFORMATION PRESENTATION RECONCILED`。

失败：`TRANSFORMATION_COSTUME_GENERIC_FAIL / STYLE_FAMILY_DEFAULT_COLLAPSE / TRANSFORMATION_SPLENDOR_FLAT_FAIL / SPLENDOR_LARGE_SCALE_MISSING / COSTUME_GRAPHIC_STRUCTURE_FAIL / SPLENDOR_MATERIAL_FLAT / TRANSFORMATION_BOLDNESS_SUPPRESSED_FAIL / TRANSFORMATION_BODY_IDENTITY_DRIFT / TRANSFORMATION_BODY_BEAUTY_SUPPRESSED / TRANSFORMATION_BODY_PRESENTATION_TEMPLATE_COLLAPSE`。

## 3｜Identity Continuity（身份连续性）

变身前后必须先让观众认出“这是同一个人”，再看见“这个人成为了怎样的圣谱者”。

### P0必须继承
- `Face Identity Matrix`中的基础脸型、面中、下颌/下巴、鼻/嘴与眉眼关系；
- 年龄感；
- 眼型大小与相对位置；
- `Hair Identity Architecture`中的发际线、分缝/刘海、Face-framing与主要后发轮廓；
- 身高、体型、肩宽、四肢比例；
- 剧情确认的永久身体特征。

### 允许变化
- **普通可恢复伤口的身体状态**：成功完成合法完整变身时可触发`TRANSFORMATION_RECOVERY`，旧开放伤口/活动性出血与由该伤口直接造成的临时身体限制不必继承到完整Transformation State；
- 虹膜 / 瞳孔内部结构；
- 眼线、眼影、眼下谱纹；
- 发束响应共鸣后的舒展、局部重组、发饰生成；
- 发色沿发束的角色专属变化；
- 战斗礼服、谱核、武器与局部共鸣光效。

### Personal Adornment Continuity
若Normal Character Master存在稳定个人装饰，变身前必须读取`personal_adornment_identity_system.md`并记录`Pre-Transformation Adornment Snapshot`：Active AC IDs / Holder / Placement / State / Current LOOK Binding，再明确：
`Adornment Transformation Rule = RETAIN / REMOVE / ABSORB / TRANSLATE / REPLACE`。

- REMOVE视为REMOVE/STOW，必须有Holder / Location / State；不得“自然消失”；
- ABSORB只有Canon World Mechanic允许实体物件被Transformation结构吸收时才合法；
- TRANSLATE若只是视觉Echo，原物件仍按RETAIN或REMOVE/STOW存在；若物理转化必须有Canon机制；
- REPLACE只描述变身专属新装饰，原日常物件仍必须有独立物理去向。

不得让耳饰、项链、戒指、发针等在TF-01里无因消失或随机变成另一件。变身专属装饰可以音乐化，但不能代替Musical Eye Motif，也不能用堆音符首饰代替真正的Beauty Core设计。

### Transformation Recovery Mechanic（变身修复世界机制）

在`Transformation Start → Completion`过程中必须记录：
- `Pre-Transformation Injury Snapshot`；
- `Recovery Eligibility = ELIGIBLE / PARTIAL / NOT ELIGIBLE`；
- `Recovery Trigger = FULL TRANSFORMATION COMPLETION`；
- `Post-Recovery Injury State`。

默认规则：
1. **ELIGIBLE**：普通可恢复的割伤、刺伤、撕裂伤、擦伤、淤伤、活动性出血，以及由这些伤口直接造成的临时肢体限制，可在完整变身完成点真实恢复；
2. **变身态不继承旧伤视觉**：若已RECOVERED，TF/Storyboard/Video不得为了旧Continuity继续画开放伤口、持续出血或旧伤导致的跛行/护伤动作；
3. **解除变身不回滚伤口**：Recovery改变的是身体World State，不是礼服遮盖。解除变身后继续使用Post-Recovery Injury State；
4. **衣物/环境独立守恒**：变身前Daily衣物已有血迹/破损、地面血迹、场景破坏不会因为身体恢复自动清除；
5. **不自动恢复的范围**：独立Fatigue、圣约/Lore Cost、永久疤痕与永久身体特征、最新Canon明确不可逆/不可被变身修复的损伤、以及已确认死亡；
6. **Partial/Failed Transformation不默认治疗**：只有完整变身完成才触发；若剧情明确存在特殊半变身修复，再由最新Canon单独授权。

P0失败：`TRANSFORMATION_INJURY_RECOVERY_FAIL / POST_TRANSFORMATION_INJURY_ROLLBACK_FAIL / TRANSFORMATION_RECOVERY_OVERREACH_FAIL`。

### 禁止
- 变身后突然换成另一张脸；
- 眼睛尺寸大幅改变；
- 发量无理由增加数倍；
- 日常人物的脸被“战斗妆”重画成另一个角色；
- 因变身而切换到高饱和魔法少女、3D游戏、真人概念图等另一套渲染风格。

## 4｜Project Style Integration（项目画风整合）

所有变身资产必须继续遵守 `project_style_dna.md`：

- anime-influenced 2D illustrated character art；
- clean hand-drawn linework；
- matte painted skin；
- controlled color blocking + soft painterly shading；
- idealized European facial structure；
- rich but restrained cinematic palette with selective saturation；dark when appropriate, never colorless；
- 人物与环境属于同一二维绘画系统。

### 4.1 Transformation FX ≠ Threat Layer

普通圣谱者的共鸣谱线、变身粒子、发色余振、武器生成光迹属于 **Transformation FX Layer（变身特效层）**，不是默认的 Threat Layer（威胁层）。

只有剧情明确为敌对、污染、失控、噪骸化或异常残响时，才允许调用 Threat Layer 的裂纹、黑弦、烧焦、破碎面具等异质语言。

## 4.2｜Music Identity & Beauty Core Five Gate

在建立正式TF / TE / TH / TC / WP前必须完成两步：

1. 读取 `music_identity_mapping.md`，建立Music Identity Card；
2. 读取 `transformation_beauty_core_five.md`，把同一个音乐身份分别转译为礼服、眼影/眼周、头发、瞳孔/虹膜、音乐武器。

P0失败条件：
- 只用颜色区分音乐风格；
- 五核心像五套独立设计，彼此没有共同节奏/符号/材质语言；
- 音乐武器只是普通刀枪贴音符；
- 角色写“悲伤/摇滚/回忆”等标签，但视觉结构和动作节奏没有发生对应变化；
- 未经剧情/用户批准就把推导方向冒充正式曲名、调式或作曲家设定。

## 4.3｜Transformation Asset Aspect Ratio Gate（变身资产比例闸门）

所有变身资产先读取 `asset_aspect_ratio_authority.md`。其中负责完整人物身份/造型的：
- `TF-01`：固定9:16竖向高分辨率2×2四视图；
- `DF-01 / DF-02 / TH-01 / TC-01`：默认9:16竖版。

`TE-01~05`为眼部专项特写、`WP-01`为武器、`TS-01`为时序、`FX-01`为特效拆解，它们按自身任务结构决定比例。**这些专项资产采用横版时，也不得把TF-01或人物母图带回16:9。**

## 5｜Core / Optional Asset Set（核心 / 按需资产组）

### 5.1 Core Transformation Master Set（核心变身母资产组）

角色正式建立变身体系后，以下资产组成其Canonical Transformation Master Set（正式变身母资产组）：

- `TF-01`｜Transformation Turnaround：变身2×2四视图；
- `TE-03`｜Official Transformed Eyes：完整变身标准眼部；
- `TH-01`｜Transformed Hair Structure：变身头发结构 / 渐变；
- `TC-01`｜Transformation Costume Structure：礼服结构；
- `WP-01`｜Weapon Master：剧情确认的圣谱者武器。

**这五项是“正式母资产组”，不是“每个镜头都必须一次性全引用”。** 下游由 `reference_resolver.md` 按镜头职责选取真正需要的资产。

### 5.2 Supporting Assets（支持资产）

- `DF-01`｜变身标准正脸；
- `DF-02`｜变身标准3/4脸；
- `TE-01`｜日常 / 人类眼部基线；
- `TE-02`｜变身启动眼部；
- `TE-04`｜战斗聚焦眼部；
- `TE-05`｜角色专属异常 / 成长状态；
- `TS-01`｜变身时序关键帧。

### 5.3 Optional Assets（按需资产）

- `TM-01`｜Material & Motif Sheet（材质与纹样页）：只有当礼服 / 武器纹样复杂、跨镜头容易漂移时建立；
- `FX-01`｜Transformation FX Sheet（变身特效拆解页）：只有当变身介质、谱线轨迹、粒子、环境反射或技能余振复杂时建立。

不为“资产清单完整”机械生成 TM / FX。

## 6｜TE-01～TE-05 Eye State System（五档眼部状态）

### TE-01｜Human Baseline（日常人类基线）
- 保持自然虹膜、自然睫毛和角色原眼型；
- 变身符号不可提前完整出现；
- 只允许剧情明确的极弱伏笔。

### TE-02｜Transformation Start（变身启动）
- 表现“形成过程”，不能直接跳到完成；
- 必须执行该角色Approved / Candidate `Formation Sequence`；
- 优先顺序是`Primary Signature emergence → Secondary Graphic lock → optional Periocular Accent → micro-detail settle`；
- Primary可以从Iris / Eyeliner / Eyeshadow任一主通道出现，不要求所有角色都先出现标准音符；
- 不同圣谱者不得机械共享同一Formation Order；
- 最终必须收束到TE-03 Canon，不在过程里发明第二套眼部图形。

### TE-03｜Official Transformed State（完整标准变身眼部）
TE-03是该角色**Eye Design Authority + Musical Eye Canon Authority**。必须锁定：
- Base Eye Identity连续性；
- `Eye Makeup Presence`；
- `Primary Eye Signature + Primary Channel`；
- `Secondary Graphic Signature`；
- `Periocular Emblem`（若有）；
- `Musical Origin Source / Translation Level / Origin Trace`；
- Core Pupil / Iris Architecture；
- Graphic Eyeliner / Eyeshadow Silhouette；
- Symmetry / Side-View Read；
- Material / Color Supporting Fields；
- Formation Sequence核心顺序；
- Costume / Hair / Weapon Cross-Core Echo；
- Registry Collision Result。

**Graphic Priority Lock：** Primary只能有一个视觉主导者；Supporting Fields不能把它稀释成“每处都有设计”。

**Musical Trace Lock：** 最终可以是`DERIVED_MUSICAL_GLYPH / MUSICAL_GEOMETRY`，不要求标准Notation仍肉眼可读；但Music Identity→Graphic的来源必须可解释，不能退化成普通幻想眼妆。

**Readability Lock：** TF-01 FRONT/SIDE至少保留Primary Graphic；CU/ECU由TE-03读Iris / Secondary / Periocular细节。

**Exact Inheritance：** TE-03 APPROVED后，下游精确继承Primary / Secondary / Iris / Graphic Silhouette / Accent / Side-view / Formation，不自由通用化。

**Registry Commit：** TE-03批准后，把`Primary + Secondary + major geometry`写入`musical_eye_motif_registry.md`作为Reserved Signature。

### TE-04｜Combat Focus（战斗聚焦）
- 不新增任何新设计；
- 只允许既有虹膜结构、瞳孔收缩、眼神集中、局部余振发生强弱变化；
- 不因为“战斗更强”突然增加第二套瞳孔符号。

### TE-05｜Character-Specific State（角色专属异常 / 成长状态）
用于过载、康复、记忆触发、动摇、诀别、新契约等**剧情特定状态**。

必须在 TE-03 原设计上变化，不能借状态变化替换成另一名角色的眼睛设计。

### Eye Design Record（眼部设计记录）
新增圣谱者时至少记录：
- 日常 / 变身虹膜色；
- 瞳孔符号；
- 环 / 线结构；
- 眼影；
- 眼线；
- 眼下纹样；
- 对称性；
- 形成顺序；
- 技能余振；
- 褪去顺序；
- 骨相约束。

### 6.1 TF-01 ↔ TE-03 Authority Flow（四视图与眼部权威流程）

为避免“先要TE图片才能做TF、又要TF才能做TE”的循环依赖，首次建档按以下顺序：

1. 从角色设定建立 `Eye Signature Spec`；
2. 对项目现有Eye Signature Ledger执行Collision Check；
3. Collision PASS后，把该Spec作为**不可弱化的Design Lock**写进首版TF-01 Prompt；
4. TF-01候选的FRONT FACE必须能读出核心瞳孔与眼周结构；看不清不能以“全身整体好看”为理由批准眼部设计；
5. 基于通过的TF-01脸部身份建立/生成TE-03，并精确确认眼部细节；
6. TE-03一旦APPROVED，升级为该角色Eye Design Authority；以后TF修订和所有下游资产必须精确继承TE-03。

如果已存在APPROVED TE-03，则新TF-01 / TF修订版必须直接绑定该TE-03，不再允许文字重新解释。

## 7｜TH-01 Hair Transformation Rules（头发变身规则）

先读取`hair_identity_architecture.md`。

- 保留日常Hair ID的发际线、分缝/刘海、Face-framing、长度逻辑与主要后发轮廓；
- 变身后发型允许在长度、体积、造型、光泽、发饰与运动张力上做明显增强：发束舒展、编发/盘发展开、半扎结构重组、发饰生成、光泽提升均可；
- 变身发型可比日常更惊艳、更具传播力，发型可承担变身状态的第一眼吸引力；
- 禁止凭空增加数倍发量（防穿帮）；长度/体积增强必须仍能从发际线与轮廓认出原角色；
- 发色变化必须沿真实发束发生，不做现代染发广告式平面渐变；
- 角色之间的颜色、覆盖范围、边界形态必须有区别；
- 渐变可从发梢向上蔓延，但若已批准角色拥有不同规则，以该角色Canonical Master为准；
- TH-01要读得出发根 / 中段 / 发梢、渐变范围、发饰位置、正侧背结构。

## 8｜TC-01 Costume Rules（圣谱者礼服规则）

### 8.1｜Iconic Costume Gate（图标化礼服闸门）

TC-01必须先读取`transformation_splendor_architecture.md`并记录：
- `Transformation Costume Thesis`；
- `Style Family`；
- `Boldness Dial`；
- `Primary Costume Signature`；
- `Secondary Costume Signature`；
- `Tertiary Accent`（0–1）；
- `Graphic Block Plan`；
- `Negative Space Architecture`；
- `Body-Line Emphasis`；
- `Material Contrast`；
- `Music Identity Structural Translation`。

**Dark Gothic / Gothic Romance只是可选Style Family，不是默认答案。** 允许但不限于Opera Couture、Avant-garde、Art Deco、Ballet-derived、Ceremonial、Mythic、Military Deconstruction、Glam、Minimal Monumental、Instrument-Architecture等。

### 8.2｜成年角色Boldness

所有成年圣谱者同时读取`character_appeal_silhouette_system.md`与`wardrobe_diversity_design_matrix.md`。

允许`RESTRAINED / ASSERTIVE / BOLD / EDITORIAL`：
- 女性可大胆利用肩颈、锁骨、胸腰臀、背部、腰腹、长腿与臀腿比例；
- 男性可大胆利用肩胸背、腹部、窄腰、前臂、颈侧、长腿；
- 允许深V、大开口、结构性胸腹开洞、侧腰切口、露背、高开衩、透视、镂空、短长极端反差、贴身束身、强不对称、极端肩/袖/裙尾比例；
- 允许**比基尼式上衣（bikini top）、高开衩到腰、大面积透视/透明层、低腰露髋结构**等更暴露的礼服结构；Exposure Geometry本身可以作为礼服的核心设计语言，但必须与角色Music Identity/人格一致，且不全员套同一暴露模板；
- 允许丝袜/长靴、珠宝、蕾丝、漆面、镜面、透明层等成为角色语言；
- **禁止的是无主次复制，不是大胆元素本身。**

如果批准的是BOLD/EDITORIAL方向，却被自动修回高领、长袖、暗色全包或身体线条不可读，判`TRANSFORMATION_BOLDNESS_SUPPRESSED_FAIL`。

未成年角色不使用成人性感规则。

### 8.3｜Hero Decisions与Graphic Structure

礼服先锁2–3个Hero Decisions，再建立：
- Large Silhouette；
- Graphic Color Blocks；
- Skin / Sheer Negative Space；
- Medium Architecture；
- Material Contrast；
- Small Detail。

`Flat Color Test / Costume Icon Test / Thumbnail Test / Negative Space Test`任一失败，不能靠追加金线、宝石、音符、刺绣补救。

### 8.4｜Material Contrast

允许更大胆的材质对撞：
`matte ↔ lacquer / mirror / polished metal`、`velvet ↔ glass / enamel`、`opaque ↔ sheer / translucent`、`soft ↔ rigid`、`heavy ↔ floating`。

Transformation材质不强制全部轻旧化；当Music Identity支持时，可出现超自然洁净、珠光、镜面、玻璃、发光纤维等。统一的是二维Render Style，不是每个人都旧金+暗布。

### 8.5｜Music Identity结构化

音乐身份必须至少进入Large Form / Medium Geometry / Material-Motion三层中的两层。标准音符可以使用，但不是唯一终点。

### 8.6｜功能性

Hero Concept先成立，再解决角色如何：跑动、转身、举臂、下蹲/横移、握持与挥动武器。功能修正不能把Primary Costume Signature全部磨平；需要调整时优先改连接、材质、活动区和物理分层。

### 8.7｜禁止

- 所有女性同一深V+高开衩或短裙黑丝；
- 所有男性同一开襟胸肌/高领长外套；
- 所有圣谱者无理由收敛为暗黑哥特；
- 只换主色制造新角色；
- Small Detail代替Hero Signature；
- 裁片前后无法连接；
- 为“合理”把强概念修成普通安全礼服。

## 9｜WP-01 Weapon & Accord Baton（武器与圣约指挥棒）

### 9.1 必须区分两类物件

**Accord Baton（圣约指挥棒）**
- 是建立合奏圣约的功能物；
- 在礼服完成时由共鸣谱线凝聚；
- 由圣谱者抛 / 交给已链接乐监；
- 乐监接住时掌心出现节拍纹，合奏圣约正式激活；
- 不作为圣谱者常规攻击武器；
- 战斗结束时与Virtuoso Weapon、Transformation Costume进入同一解除阶段同步消散。

**Virtuoso Weapon（圣谱者武器）**
- 是角色真正的攻击 / 防御 / 共鸣武器；
- 必须是剧情确认的角色专属设计；
- Linked状态下，在乐监接棒、节拍纹出现后才从共鸣中生成；
- 与眼睛、头发、礼服使用同一视觉语法；
- 武器存在本身持续消耗合奏圣约负担。

若角色武器名称含“棒”，必须明确它是不是Accord Baton，禁止二者混淆。

## 10｜TS-01 Transformation Timeline（变身关键帧时序）

> **重要：** 正式九关键帧时序必须服从当前世界观机制：礼服与谱线先完成，Accord Baton形成并由已链接Maestro接住、节拍纹出现后，Virtuoso Weapon才生成。

### 10.1 Linked Transformation（有已链接乐监）默认九关键帧

1. **Daily State**：日常状态，触发物 / 谱核仍安静；
2. **Resonance Trigger**：共鸣激活，日常瞳孔开始失焦 / 裂变 / 重组；
3. **Eye + Costume Initiation**：专属瞳孔开始形成；礼服从肩线与腰线开始成形；
4. **Score-Line Propagation**：眼部结构继续完成；角色专属谱线从眼角 → 胸前谱核 → 腰际推进；
5. **Costume Completion**：礼服主要裁片与纹样完成，谱线推进至衣摆 / 裙摆；
6. **Hair Completion + Baton Formation**：发梢完成角色专属变身色 / 余振；礼服完成的同时，Accord Baton在圣谱者手中凝聚；
7. **Baton Handoff**：圣谱者把指挥棒抛 / 交给已链接乐监；
8. **Accord Activation + Weapon Formation**：乐监接住，掌心节拍纹出现；合奏圣约激活，圣谱者武器随后生成；
9. **Battle State Lock**：角色睁眼 / 完成一次呼吸 / 重心进入战斗状态，正式变身完成。

首次变身或剧情明确的终结技，可以加入“世界短暂停顿一拍”的演出；普通重复变身不机械放大成同样长度的华丽演出。

### 10.2 Solo Transformation（无已链接乐监）分支

前6步可与Linked一致。之后：

7. Accord Baton凝聚，但没有乐监接取；
8. Baton在数秒内自行消散，**标准契约武器不生成**；
9. 圣谱者进入独奏状态，以自身共鸣强行维持剧情已确认的攻击表现，代价由本人承担，稳定性更差。

如果某角色Canonical Story / Approved Master明确存在独奏例外，以该角色已确认设定为准，不能用本通用规则反向改写剧情。

### 10.3 De-Transformation（褪去）

战斗结束后进入同一个解除阶段：

**Virtuoso Weapon + Transformation Costume + Accord Baton同步开始消散**；礼服内部可继续表现外层裙片 / 衣摆 → 发尾变身色 → 妆容 / 眼下纹样 → 瞳色 / 虹膜结构的视觉退场顺序，最后完全恢复当前剧情阶段日常服装。若该人物存在Character Closet / Wardrobe State Ledger，必须恢复**战斗开始前同一Daily LOOK ID与Runtime Configuration**（例如COAT_OPEN、GLOVES_OFF、WET等），不得回到默认服装、错误季节Look或自动把穿脱/湿度状态刷新；同时恢复`Pre-Transformation Adornment Snapshot`中的准确Active Adornment / Holder / Placement / State，除非战斗中已有明确丢失、破损或转交Transition。

P0：不得出现礼服已经完全解除、但战斗武器或Accord Baton仍作为实体残留的状态。乐监掌心节拍纹随解除平息。若刚释放终结技，整个解除阶段可以更慢，并遵守剧情中的再变身限制。

## 11｜Transformation FX（变身特效）

FX不是“越亮越强”。优先表现：
- 角色专属介质（谱纸、弦线、几何刻纹、冰裂、羽状残响等已批准语言）；
- 形成方向；
- 速度 / 节奏；
- 与呼吸、动作、音乐身份相匹配的位移；
- 环境表面上的局部反射与空气响应。

禁止：
- 全身霓虹爆闪；
- LED式眼球；
- 无意义满屏粒子；
- 高饱和彩虹魔法少女特效；
- 为“华丽”而覆盖人物脸、礼服结构或武器轮廓。

## 12｜Reference Binding（参考图职责）

### 建立新变身资产
默认职责顺序：
1. `Render Style Anchor / Project Style DNA`：只管怎么画；
2. `Approved Normal Character Master`：只管变身前是谁 / 脸 / 基础发型 / 身材；
3. 当前已批准Transformation Master（若已有）：只管变身设计结构；
4. 当前具体任务资产：例如TE / TH / TC / WP；
5. Storyboard / Ending Frame：只管动作、空间和连续性。

Render Style Anchor负责项目级绘画语言；角色身份与当前造型由各自APPROVED Character Master负责。任何单一角色图都不得取代项目级Render Style Authority；若使用Cinematic Shot Style，它只在分镜/视频阶段控制摄影语法。

### 下游引用
`TF-01 / TE-03 / TH-01 / TC-01 / WP-01` 是Canonical Master Set，但每个镜头只选职责相关项：
- 眼睛/眼妆可读特写：Character / TF + 当前TE；若已有APPROVED TE-03，它是`TRANSFORMATION_EYE_SIGNATURE / MUSICAL_EYE_MOTIF`最高职责资产；
- TF-01修订 / 重生：若已有APPROVED TE-03，必须把TE-03作为Eye Design Authority加入Reference Pack，禁止仅凭文字重猜眼睛；
- 发色 / 发饰特写：TF + TH；
- 全身礼服：TF + TC；
- 武器动作：TF + WP，必要时TC；
- 完整变身过程：优先TS-01 + TF；需要锁眼睛 / 礼服 / 武器时再加入对应细节资产；
- 不因“资产齐全”把五项全塞进每个中景镜头。

## 13｜Prompt Assembly（变身资产Prompt拼接）

正式Prompt按以下顺序内部编译：

1. `STYLE`｜Project Style DNA；
2. `IDENTITY`｜Approved Normal Character Master；
3. `TRANSFORMATION IDENTITY`｜来源 / 人格 / Accord / Character Theme；
4. `MUSIC IDENTITY CARD`｜Emotion Core / Personality Core / Music Direction / Rhythm Profile / Visual Grammar，并标明CANON或DERIVED；
5. `BEAUTY CORE FIVE`｜礼服 / 眼影眼周 / 头发 / 瞳孔虹膜 / 音乐武器五项转译；
6. `ASSET FORMAT`｜TF / TE / TH / TC / WP / TS / TM / FX；
7. `EYE SIGNATURE + MUSICAL EYE CANON`｜Base Eye + Primary Eye Signature + Secondary Graphic + optional Periocular + Musical Origin Trace + Registry Collision；TF / TE必须显式写入，不能只写“独特眼睛/音乐感眼妆”；
8. `DESIGN LOCK`｜五核心 + 介质专属结构；
9. `TIMELINE`｜仅TS需要，使用Linked或Solo分支，并继承Motion Grammar；
10. `CONSISTENCY`｜变身前后同一人物、前后视图 / 各状态一致；
11. `RESTRICTIONS`｜当前角色真正高风险的负面项；眼部只追加真正高风险的撞型负面锁，例如“不得复用最相近角色的Primary Eye Signature / Iris Architecture / Secondary Graphic”，不重新堆一套长负面清单。

不要把所有负面词、所有资产描述、所有变身阶段机械重复到每一个小资产Prompt里；以“当前资产能稳定复现”为目标。

## 14｜Transformation QC（变身资产质检）

### Music Identity / Beauty Core Five
- [ ] 已建立Music Identity Card，并区分CANON与DERIVED信息；
- [ ] 人格 / 情绪 / 人物弧与音乐方向之间有可解释关系，不是机械“一个形容词=一种音乐”；
- [ ] 礼服 / 眼影 / 头发 / 瞳孔 / 音乐武器五核心都来自同一Visual Grammar；
- [ ] 五核心在审美上各自成立，同时没有互相抢戏；
- [ ] 音乐武器体现乐器/声部结构、演奏动作与战斗功能，不是普通武器贴音符；
- [ ] Supporting FX没有遮住五核心；
- [ ] 未擅自编造具体调式、曲名或作曲家作为Canon。

### Identity
- [ ] 变身前后首先仍然能认出同一个人；
- [ ] 脸型、年龄、眼型、身材未漂移；
- [ ] 变身没有切换渲染风格。

### Eyes
- [ ] 已建立Eye Signature Spec，并读取Eye Signature Ledger / Musical Eye Registry；
- [ ] Eye Makeup Presence不是NONE / ABSENT；
- [ ] Primary Eye Signature一句话可记住，且只有一个主视觉中心；
- [ ] MAIN/CORE拥有Secondary Graphic；Periocular Emblem若存在只作为Accent；
- [ ] Music Identity通过`LITERAL_NOTATION / DERIVED_MUSICAL_GLYPH / MUSICAL_GEOMETRY`之一进入眼部；不要求标准Notation贴脸，但Musical Origin Trace真实成立；
- [ ] 没有“普通眼妆 + 音符贴纸”；
- [ ] Base Eye与最相近角色至少3项非颜色结构不同，Transformation Primary/Secondary组合无碰撞；
- [ ] 中距离能读Primary，CU/ECU能读Iris / Secondary / Accent；
- [ ] Supporting Fields没有把眼部堆成多个同等级焦点；
- [ ] TE-01→05是同一眼型的状态变化；
- [ ] TE-04没有新增设计；TE-05只改变剧情状态；
- [ ] 已有APPROVED TE-03时，下游精确继承Primary / Secondary / Iris / Graphic Silhouette / Accent / Side-view / Formation。

### Hair
- [ ] 基础发型身份仍可识别；
- [ ] 渐变沿发束发生；
- [ ] 渐变起点、范围、边界和发饰与Master一致；
- [ ] 没有无理由暴增发量。

### Costume
- [ ] Costume Thesis可以一句话概括，不是泛化“暗黑华丽礼服”；
- [ ] Dark Gothic仅在角色确实需要时使用，没有成为默认风格；
- [ ] Primary / Secondary Costume Signature清楚，Tertiary最多1个；
- [ ] Graphic Block / Negative Space在移除小纹样后仍成立；
- [ ] 成年角色Boldness Dial与角色定位一致，没有被“高级/克制”无理由压回保守；
- [ ] Body-Line / Exposure Geometry是主动设计，不是全员模板；
- [ ] Body Identity与Normal Character Master连续；已建立Transformation Body Presentation Mode，礼服通过直接呈现/框景/比例/暗示/对比等适合角色的方式让既定Appeal继续成立，而不是被华丽体量无理由吞掉；
- [ ] Material Contrast有强弱层级，允许角色专属高光泽/透明/硬质/珠光等大胆材质；
- [ ] Music Identity真正改变Large Form / Medium Geometry / Material-Motion中的至少两层；
- [ ] 正背裁片可连接，可跑动、转身、举臂与使用武器；
- [ ] 与其他圣谱者不是单纯换色/换纹样关系。

### Weapon / Accord
- [ ] Accord Baton与Virtuoso Weapon没有混淆；
- [ ] Linked变身中武器只在乐监接棒后生成；
- [ ] Solo分支没有错误生成标准契约武器；
- [ ] 武器比例、握持方式与角色动作可执行。

### Personal Adornment / World State
- [ ] Personal Adornment Transformation Rule有合法World State来源；REMOVE不是凭空消失，ABSORB/TRANSLATE有Canon机制，REPLACE不抹掉原日常物件去向；
- [ ] De-Transformation恢复战斗开始前准确Adornment Snapshot，除非剧情已有有因变化；

### Timeline / FX
- [ ] TS-01时序符合当前世界观；
- [ ] 礼服、谱线、发梢、指挥棒、武器之间因果顺序正确；
- [ ] FX强化身份而不是遮住人物；
- [ ] 普通共鸣FX没有被错误画成Threat Layer；
- [ ] 首次变身 / 终结技的“一拍静默”只在剧情需要时使用。

## 15｜一句话总锁

> **观众必须先认出“这个人”，再看见“这个人如何成为自己的圣谱者”：眼睛是身份签名，头发是共鸣轨迹，礼服是人格结构，武器是契约后的行动方式，变身时序则必须服从合奏圣约的真实因果。**
>
> **Eye Signature不得是“所有圣谱者共享一套漂亮眼妆再换颜色”。核心瞳孔、虹膜拓扑、眼影轮廓、眼下纹样与对称逻辑必须形成角色级视觉指纹。**
