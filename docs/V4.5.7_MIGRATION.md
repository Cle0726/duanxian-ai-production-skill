## 旧项目迁移
1. 现有Approved Master保持Approved，不要求重生。
2. 对历史Approved图片若无法恢复Generation Job，可登记`generation_job_id: null`并标记`MIGRATED_LEGACY_EVIDENCE`；新生成资产从V4.5.7开始必须有Job。
3. 对每个会进入后续生成的新Scene/Look Domain：从Approved Base/Global Color Card自动派生Scene Color Card；已有等价Approved Scene Card直接映射复用。
4. Coverage / Shot Execution / Video新资产必须写`lineage`和`scene_color_authority_id`。
5. Named Asset平台继续真实`@资产`；其它宿主由Host Adapter映射Native Reference，不伪造Token。
6. 历史`DERIVED_COVERAGE_VIEW / EVENT_NODE_VIEW / RECIPROCAL_COVERAGE_VIEW / PREDICTIVE_COVERAGE_VIEW / SCENE_CLUE_VIEW / LOCATION_VISIBILITY_VIEW / LOCATION_IDENTITY_VIEW`可继续读取；新生产统一迁移为`ENVIRONMENT_COVERAGE`，原语义写入`coverage_reason_codes`。
7. 不要求仅为改名重生历史Approved Coverage；只有需要新生成/返修时才用当前类型重建。

## Release Gate
必须通过`tests/run_v457_execution_tests.py`与`tests/run_v457_integrity_tests.py`。Coverage迁移兼容另外由`tests/run_v457_coverage_migration_tests.py`验证：旧项目可读、新项目不得继续生产旧Coverage类型。
