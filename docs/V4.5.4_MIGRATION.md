# V4.5.4 Migration — Required View Realization Gate

V4.5.4修复“Skill声明支持多视角，但关键方向可能没有真正生成”的闭环缺口。

## Existing V4.5.3 workspace
1. 保留已有Spatial Canon、Asset Registry、Visual Evidence，不要求重做场景。
2. 把每个Event Node现有`required_view_roles`物化为`SPATIAL_CANON.view_requirements`。
3. 对每条Requirement补`Camera Origin / Optical Axis / Must See Anchors`；不要只复制FORWARD/REVERSE标签。
4. 运行`tools/view_coverage_planner.py`扫描现有资产；已有Coverage通过`derivation.view_requirement_ids`绑定对应Requirement。
5. 只有Current Visual Evidence真正证明方向/Anchor的图片才能设为`selected_fulfillment_asset_id`。
6. 对MISSING项只补最小视角；不要重做已经正确的其它资产。

## New hard gates
- `EVENT_REQUIRED_VIEW_UNMATERIALIZED`：Event要求视角但没有具体Requirement。
- `REQUIRED_VIEW_ASSET_MISSING`：Requirement没有任何候选资产。
- `COVERAGE_BUDGET_STARVES_REQUIRED_VIEW`：仍缺关键方向却继续在已覆盖方向超预算抽图。
- `REQUIRED_VIEW_ROLE_VISUALLY_UNPROVEN / REQUIRED_VIEW_AXIS_VISUALLY_UNPROVEN`：图片实际方向与声明不符。
- `REQUIRED_VIEW_VISIBLE_ANCHOR_GAP`：必须看见的固定Anchor在图里不可见。

V4.5.3 Visual Evidence规则继续有效；V4.5.4只是把Evidence进一步用于证明“视角真的实现了”。
