# V4.5.6 Migration — Logic Integrity & Adversarial Regression

V4.5.6 is a closure release. It does not add a new creative engine. It fixes false-pass/false-fail paths discovered after V4.5.5 Everyday Realism entered production.

## Required migration actions

1. Existing V4.5.5 `REALISM_CONTRACT` records may remain readable. When touched by V4.5.6, add `reality_basis` and use lifecycle `DRAFT → QC_PASS_WAITING_APPROVAL → LOCKED`.
2. Every ordinary V4.5.6 `IMAGE` asset must declare `realism_applicability`:
   - `REQUIRED` — bind one or more applicable Reality Contracts;
   - `SCOPED_EXCEPTION` — still bind the contract and name only an exception whose scope actually contains this asset/shot/event/scene;
   - `NOT_APPLICABLE` — provide `realism_applicability_reason` and use `realism_qc_status: NOT_APPLICABLE`.
3. Reusable `VEHICLE` locations require an approved `VEHICLE_LAYOUT`; this is now accepted by `spatial_canon_lint.py` instead of being falsely rejected as a missing reusable-set diagram.
4. For functional circulation, migrate required paths into `SPATIAL_CANON.locations[].access_paths` and reference them from `REALISM_CONTRACT.environment_requirements.required_access_path_ids`.
5. Visual Evidence for reality-sensitive assets should record fine-grained fields where relevant. A specific FAIL is authoritative over a coarse category PASS.
6. Storyboard, Video Conditioning and pre-video reference selection now invoke Everyday Realism again. Actual video QC additionally requires fingerprint-matched multimodal/human `QC_RUNTIME.video_realism_evidence`.
7. Failure routing resolves exact validator codes first, then `controller/failure_router.yaml:code_aliases`. Unknown hard codes block release rather than falling through silently.

## Do not mass-regenerate old approved assets

V4.5.6 is not a forced visual reset. Existing approved V4.5.5 assets can be migrated on demand. Add applicability/bindings when the asset is next reused; only assets that fail current evidence or current Reality Contract need regeneration.
