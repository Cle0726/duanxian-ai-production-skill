# V4.2.7 → V4.3.1 Migration Notes

## 目标

V4.3不删除《断弦之歌》的深层创作Authority，主要把控制面、状态面、Runtime面分开。

## 关键变化

- `SKILL.md`：从大型Knowledge+Router收敛为Production Controller。
- `templates/load_on_demand_controller.md`：改为兼容入口；唯一Route表迁移到`controller/route_registry.yaml`。
- `templates/一人制片自动执行与生产闸门.md`：改为兼容入口；唯一状态机迁移到`controller/workflow_state_machine.yaml`。
- `templates/system_integrity_authority.md`：只保留Cross-Module Invariants。
- `templates/runtime_efficiency_system.md`：只保留Runtime Compile/Invalidation规则。
- `templates/episode_workspace.md`：由Markdown总账升级为结构化State说明。
- 新增`controller/authority_registry.yaml`与`controller/failure_router.yaml`。
- 新增`state/*.schema.yaml`、`runtime/*.schema.yaml`。
- Web QC硬编码配置迁移到`adapters/web_qc/platform_profile.yaml`。
- 新增确定性命名、Fingerprint、Archive工具与V4.3架构/Schema Smoke Tests。

## 兼容策略

旧模板文件名尽量保留，因此旧文档引用不会立即断裂。兼容入口明确指向新的唯一机器Authority，避免两套Route/State Machine继续漂移。

## Regression说明

`tests/fixtures/`只做结构Smoke Test，不代表《断弦之歌》Canon。真实Golden Episode应从现有Approved项目素材建立，见`tests/golden_episode/README.md`。

## V4.3.1 Generation Asset Mention Correction

V4.3.0继承V4.2.7的“默认不输出@图N/仅平台明确要求时保留Native Token”策略，这与《断弦之歌》当前生产约定不匹配。V4.3.1将Generation Reference Surface改为`NAMED_ASSET_MENTION_REQUIRED`：强绑定Approved Asset必须显式`@资产`调用；缺失Native Mention时不得静默降级为纯文本Prompt。
