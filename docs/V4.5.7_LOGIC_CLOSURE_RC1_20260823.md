## Closed in this RC

### 1. Readable Scoped Cast Appearance Authority is single-owner

Canonical rule:
- Readable scoped/minor human Base Appearance Authority = Approved `FMH_ASSET / MINOR_HUMAN_MASTER` only.
- `SHOT_ASSEMBLY_ASSET`, Storyboard, Mandatory Previs and Rendered Human Pose Anchor may own/support relation, placement, pose, blocking, contact, action or transient state only.
- They cannot own, co-own, share, replace or bootstrap human Appearance Authority.

Removed/rewritten active-template loopholes including:
- Assembly claiming `SCOPED_CHARACTER_APPEARANCE_AUTHORITY`.
- `FMH_NURSE_A or ASM_HOSPITAL_DELIVERY` as interchangeable Appearance coverage.
- `FMH / Assembly / Approved Previs Human Anchor` as interchangeable visual owners.
- `SCOPED_CAST` exceptions that allowed Assembly to substitute for identity/appearance.
- ambiguous wording that prohibited only the "unique" Assembly/Previs Appearance Owner while leaving shared ownership open.
- `Identity/Human Appearance -> Character/FMH/Shot Assembly/Previs Human Anchor` owner list.

`validators/v457_architecture_lint.py` now statically rejects regressions of these patterns in active templates.

### 2. Contact Sheet derived-panel physical proof is mandatory

`validators/storyboard_contact_sheet_lint.py` now requires every split panel to have:
- manifest `file_path` present;
- manifest file physically present;
- actual file SHA256 equal to manifest SHA256;
- registry fingerprint equal to actual file SHA256;
- registry `file_path` present;
- registry file physically present;
- registry and manifest paths resolving to the same file.

New hard failures include:
- `CONTACT_SHEET_SPLIT_FILE_PATH_MISSING`
- `CONTACT_SHEET_SPLIT_FILE_MISSING`
- `CONTACT_SHEET_SPLIT_REGISTRY_FILE_PATH_MISSING`
- `CONTACT_SHEET_SPLIT_REGISTRY_FILE_MISSING`
- `CONTACT_SHEET_SPLIT_REGISTRY_FINGERPRINT_NOT_ACTUAL_FILE_SHA`
- existing `CONTACT_SHEET_SPLIT_FILE_SHA_INVALID`
- existing `CONTACT_SHEET_SPLIT_FILE_PATH_MISMATCH`

Adversarial tests now cover missing path, nonexistent derived file and registry path substitution.

### 3. Performance Contact Support closes the actual interaction entity

`validators/performance_asset_requirement_lint.py` now requires:
- every referenced performance support asset to bind exactly to its `performance_requirement_id`; null is no longer accepted;
- `PERFORMANCE_CONTACT_POSE_SUPPORT` to declare `performance_interaction_entity_ids`;
- contact entities to be a subset of the requirement's allowed interaction entities;
- required interaction entities to be covered by the contact support assets;
- `PERFORMANCE_SUPPORT_PACK` with `CONTACT_RELATION` to declare interaction entities as well.

`state/asset_registry.schema.yaml` now exposes `performance_interaction_entity_ids`.

This prevents "correct performer, wrong person being held/touched/supported" from passing solely because the subject entity is correct.

### 4. Narrative FX Scope is mechanically self-consistent

`state/narrative_fx_asset_manifest.schema.yaml` now requires:
- `scope`
- non-null/non-empty `scope_id`
- non-empty `scene_ids`
- existing non-empty `shot_ids`

`validators/narrative_fx_asset_lint.py` now checks:
- SHOT scope: exactly one shot and `scope_id` must equal that shot ID;
- SCENE scope: exactly one scene and `scope_id` must equal that scene ID;
- EPISODE scope: `scope_id` must equal manifest `episode_id`;
- SHOT_GROUP / SEQUENCE require a concrete scope ID;
- `recurrence_count` cannot be lower than the number of covered shots.

### 5. REALISM_CONTRACT has an explicit structured single owner

`controller/authority_registry.yaml` now registers:
- authority: `realism_contract`
- owner: `templates/everyday_realism_plausibility_gate.md`
- structured schema: `state/realism_contract.schema.yaml`
- deterministic validator: `validators/everyday_realism_lint.py`
- runtime: `REALISM_RUNTIME`

`everyday_realism_plausibility` explicitly consumes `realism_contract` rather than implicitly redefining it.

Architecture lint verifies that `state/realism_contract.schema.yaml` has exactly this structured owner.

### 6. Fresh workflow state has an explicit authority and invalid states hard fail

`controller/workflow_state_machine.yaml` now defines:
- PRODUCTION -> `SOURCE_NARRATIVE_PENDING`
- DEMO -> `SOURCE_NARRATIVE_PENDING`
- MIGRATION -> `MIGRATION_REQUIRED`

under `initial_state_by_mode`.

`state/episode_state.schema.yaml` now enumerates exactly the workflow state's legal state names.

`validators/v457_architecture_lint.py` verifies enum/state-machine equality and complete mode-to-initial-state coverage.

`tools/controller_engine.py` now returns hard failure `WORKFLOW_STATE_UNKNOWN` for a state not declared by the workflow authority instead of silently returning zero candidate transitions.

### 7. Current production and legacy Environment Coverage are explicitly layered

Current V4.5.7 physical coverage remains `ENVIRONMENT_COVERAGE` plus reason codes.

Legacy types remain readable only for old-version migration compatibility, including:
- `DERIVED_COVERAGE_VIEW`
- `EVENT_NODE_VIEW`

- `PREDICTIVE_COVERAGE_VIEW`
- `SCENE_CLUE_VIEW`

- `LOCATION_IDENTITY_VIEW`

When a Registry/Obligation set declares `skill_version: 4.5.7`, current validators now fail these legacy physical/obligation types with migration-required failures rather than treating them as current production targets.

Updated validators include:
- `asset_library_completeness_lint.py`
- `required_view_realization_lint.py`

Old-version fixtures remain accepted for compatibility/migration tests.
