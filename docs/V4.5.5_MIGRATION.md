# V4.5.5 Migration — Everyday Realism & Plausibility

## Purpose
V4.5.5 adds a project-wide **Everyday Realism & Plausibility baseline**. Ordinary scenes must remain physically, functionally, ergonomically, socially, and continuously plausible unless the source explicitly requires a local non-realistic event.

This is a logic-closure release, not a new creative style engine.

## Global rule
**Reality is the default. Exceptions are local.**

A fantasy / supernatural project does not globally waive ordinary reality. `TRANSFORMATION`, `COMBAT`, `SUPERNATURAL`, `DREAM`, `HALLUCINATION`, `SURREAL`, and `SYMBOLIC` may waive only named realism categories for named scene/event/shot/asset scopes.

A visually attractive asset that is physically, functionally, ergonomically, or socially implausible MUST FAIL. 漂亮不能抵消不合理。

## New typed state
- `REALISM_CONTRACT` — per scene/location ordinary-reality requirements.
- `REALISM_RUNTIME` — compact active contract/failure runtime.
- `VISUAL_EVIDENCE.observed.realism` — what the rendered pixels actually prove.

## Profiles
V4.5.5 validates eight categories:
1. `ENVIRONMENT_FUNCTIONAL_REALISM`
2. `ARCHITECTURAL_REALISM`
3. `VEHICLE_REALISM`
4. `HUMAN_ERGONOMICS`
5. `OBJECT_AFFORDANCE`
6. `SOCIAL_SPATIAL_PLAUSIBILITY`
7. `MUNDANE_PHYSICS`
8. `MUNDANE_CONTINUITY`

`VEHICLE` is now a first-class location kind. Important vehicles require a concrete vehicle type and `VEHICLE_LAYOUT`, including driver/control zone, passenger zones, access/circulation, front/rear direction, capacity, and relevant support surfaces.

## Existing project / asset migration
Do **not** invalidate all approved assets merely because they predate V4.5.5.

For each currently used ordinary-scene asset:
1. Bind it to the applicable `REALISM_CONTRACT`.
2. Reuse current `VISUAL_EVIDENCE` when its fingerprint matches; add `observed.realism` only when a realism-sensitive decision depends on that asset.
3. Mark planning diagrams `realism_qc_status: NOT_APPLICABLE` where pixel-level human realism is irrelevant.
4. If evidence is missing, queue only the blocking asset for visual review. Do not stop unrelated text/planning work.
5. If the old visual conflicts with explicit Source/locked Spatial Canon, keep Source/Canon and reject/regenerate the minimum affected visual. Do not rewrite Canon to preserve a pretty wrong image.
6. If the conflicting layout was only a derived/unapproved assumption, repair the upstream `REALISM_CONTRACT` / Spatial Canon first, then rederive only affected assets.

## Required View interaction
V4.5.4 Required View completion remains mandatory. V4.5.5 adds a second condition:

`CORRECT VIEW != CORRECT ASSET`

A Required View is usable only when its actual visual realization also passes the applicable realism contract. Example: a wagon forward view is still invalid if the driver/passenger layout, cast count, seating, capacity, or human support is implausible.

## Text-only continuation
V4.5.3 behavior remains unchanged:
- text-only controllers may reason from current Visual Evidence;
- they may not invent visual realism judgments;
- stale/missing realism observations block only the affected visual decision.

## Reconciliation order
On a realism failure, diagnose the owner before regeneration:

`SOURCE -> REALISM_CONTRACT -> SPATIAL_CANON / WORLD_STATE -> ASSET EXECUTION -> VISUAL_EVIDENCE`

Use minimum necessary rollback. If upstream truth is correct, reject the generated candidate. If upstream derived planning is the error, patch it before generating more images.

## Batch budget rule
Repeated candidates with the same realism failure do not count as progress. Stop the batch, repair the governing realism/spatial contract, then resume. This works together with V4.5.4 Coverage Debt First to prevent spending image credits on the wrong world or wrong view.
