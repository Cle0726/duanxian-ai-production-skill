# V4.5.7 Patch Summary

本次只补执行脊柱，不重做既有Canon/Director/Reality/QC体系。

## 已解决
1. Stage 03 Queue → Character/Environment/Prop/Transformation/Color/Support/Assembly Route自动派发。
2. 新增Generation Job / Generation Runtime，生成结果、Candidate、QC、Approval、Promotion分层。
3. 新增Host Adapter，生成能力存在时要求真实执行；能力不存在才Manual Handoff。
4. Candidate Capture与Approved Archive分离。
5. Master → Coverage → Shot Execution Frame → Video完整血缘。
6. 一个Base/Global Color Card在换Scene/Look Domain时自动派生并生成Scene Color Card。
7. Scene-bound图片与视频持续绑定对应Scene Color Card；Named Asset平台保持真实@色卡。
8. 新增Controller Engine与Runtime fingerprint compiler入口。
9. Active Route可达性检查与Generation/Color E2E + adversarial tests。
10. 综合色在Generation Job执行前成为硬门：Scene-bound图片/视频不得事后补绑；Scene Card必须Approved且Scene/Look Domain一致。
11. Stage 05 Video生命周期与Image Promotion彻底分离：Video Take只进入Video Runtime/QC，不得被`asset_promoter.py`当图片资产晋升。
12. Runtime Compiler增加Schema Closure：无法满足目标Runtime Schema时拒绝写`VALID`。
13. V4.5.7新生产的环境Coverage统一为`ENVIRONMENT_COVERAGE + coverage_reason_codes`；旧`*_VIEW`类型只保留迁移读取，新Generation Job禁止继续创建旧类型。
14. 已存在Approved Scene Color Card但Runtime映射缺失时优先同步复用，禁止重复生成综合色卡。

## 综合色最短规则
- 新Scene：先自动派生Scene Color Card。
- 场景母图/Coverage/Assembly/Shot Execution：@该Scene Color Card。
- Video：@Shot Execution Frame，同时继续@同一Scene Color Card。
- 角色/纯道具等无Scene Scope母图：@Base/Global Color Card。


## Coverage收敛
新生产只创建一个物理环境派生类型：`ENVIRONMENT_COVERAGE`。
`EVENT_NODE / RECIPROCAL / PREDICTIVE / CLUE_REVEAL / LOCATION_VISIBILITY / LOCATION_IDENTITY / REQUIRED_VIEW`只作为`coverage_reason_codes`，不再各自产生平级图片类型。
旧类型仍被Schema/Validator读取用于已有工程迁移，但V4.5.7 Generation Job会拒绝用旧类型创建新资产。
